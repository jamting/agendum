## § 6 Summary and verdict

The project paused to think, and the thinking was good: the meeting of 2026-10-21-2324 turned the owner's rough notes into a strategy (a truthful clone of Lotus Agenda first, the extras frozen and hidden behind one switch), a test for every difference (ADR 0043), a plan for the code (ADR 0044) and a path to a public repository, all written into the documents within the hour. The biggest strength is that the strategy fits what is already built: the command layer makes "hide the extras" a filter on data rather than a search through code, the `.AG` importer gives the clone its story, and the headless Agenda gives it a judge. The biggest risk is that "declared done" has a hole in it: AGENDA_PARITY's own table lists recurring items on every date as missing, yet its steps, which define done, leave them out; and the safety work the last review asked for (a closed type for effects, a recovery file, hostile-text tests) could be mistaken for frozen "Beyond Agenda" work when it is the clone's own safety. The one thing to do next: close the definition of done and tag the 31 entries in one sitting with the owner, so that the clone's look is fixed before anything is built.

## § 8 Architecture

**José** read ADR 0044 against the code. Its line is right: the extras' modules (the blog, the site, Markdown, feeds, Zettel ids) to `Agendum.Core.Extras.*`, and an `:xref` rule that faithful code reaches them only through tagged commands. But the rule as written cannot hold without exceptions. The extras are not only modules; they are stored fields of the database (`next_zettel`, `feeds`, `blog`, `lib/agendum/core/database.ex:29,42,47`), so `Database`, `JSONFile` (40 mentions of feeds, the blog and Zettel ids in `lib/agendum/core/json_file.ex`), `Store`'s golden files and `Invariants` must name the extras' types. The facade does too (28 mentions in `lib/agendum/core.ex`), and so does `TUI.Update` (45). He advised writing the allowed callers into the ADR and the test before the move (the file format's modules and the facade's extras area), so that the test is strict everywhere else from its first day.

**Joe** agreed, and added that the file format must stay one: a file saved with Extras off keeps the extras' fields (ADR 0043), so the round-trip test the ADR asks for should be written before the switch, against today's code, where it would pass; then it guards the move rather than describing it afterwards.

**José** noted that ADR 0043's "a property of the command" has no field to live in yet: `Agendum.TUI.Command` is `[:id, :name, :summary, doc: nil, count: :none]` (`lib/agendum/tui/command.ex:16`). Adding a field such as `extra: false` with a default is a small, safe change, and the menus (`Agendum.TUI.Menu.tree/0`), the keymaps, F1 and CTRL-X then filter on one thing. The menu tree names commands by id (`lib/agendum/tui/menu.ex:52-59`), so the filter can look each one up.

**Joe** raised the shell again: `App.run_effects/2` still ends without a clause for an unknown effect (`lib/agendum/tui/app.ex:209-309`), the same shape that crashed the program on 2026-10-17 (`80ab019`). The clone will be judged by people who used Agenda for years on their real files, and a crash in front of them costs more than any missing command. He counted the effect type and a recovery file as the clone's work, not as extras.

**Claude** agreed with both, and noted that ADR 0044's "the core becomes its own Mix project when the web starts" is the right time: today the TUI is the core's only user, so a split would be all cost.

## § 11 Helpfulness to users

One stood out: on 2026-10-18 at 10:23 the owner pressed for a standard view's settings and was told "A standard view's settings are in View ▸ Hide, Filter and Order". That is parity step 2, the View Properties box (`docs/plans/AGENDA_PARITY.md`, "The steps"), met in daily use, not in a plan. He advised that it be the first parity step built after the groundwork.

**David** said a trusted system needs its recurring commitments where they fall. Recurring items appear on their base date only (ROADMAP, Time management; `docs/plans/RECURRING_OCCURRENCES.md`, R14a), so a weekly meeting is not in next week's datebook. The owner raised the same wish (the imported calendar seen correctly a little into the future, in the notes below the agenda's line). He was surprised to find it outside the parity steps (§ 13).

**Carsten** looked at the clone through an old user's habits. The date format's default (ISO 8601 rather than Agenda's MM/DD/YY) is the first thing such a user sees in every view; the tagging of the 31 entries will decide it. Agenda kept a global date format setting itself (the `.AG` importer still has to bring it over, ROADMAP, Data interchange), so the faithful answer may be "Agenda's default, and the importer reads the file's own setting", which also serves the owner, whose files would keep ISO.

## § 13 Vision

**Mitch** called the meeting's decision the clearest statement of purpose the project has had: `docs/VISION.md` now says the clone comes first, why, and that the dream comes after; ADR 0043 gives one test for every difference; the roadmap's **Next:** line follows.

**David** asked what "declared done" means, and found the answer incomplete. VISION and ROADMAP define it by the steps of `docs/plans/AGENDA_PARITY.md`. That plan's own table lists four things missing from the data model and views: recurring items on every date, unindexed categories, the trash and external note files (`docs/plans/AGENDA_PARITY.md:166`). The trash is a step, unindexed categories come with step 6, external note files are in the note editor plan, but recurring items on every date are in none of the nine steps; they sit in Time management on the roadmap. A clone declared done without them would show a weekly meeting once. He asked that the steps include everything the table lists as missing, or that each omission be put on the modifications list on purpose.

**Marie** said a finish line sparks joy, and this one is the first the project has drawn. She asked only that the "later" things stay visibly later: the Beyond Agenda heading now says "Frozen to bug fixes", which is right, and the Ideas list under it needs the same line, or an idea will slip up while no one is looking.

## § 14 Agent readiness

**Claude** said: I have least to report of any lens, and that is a decision, not a failure. Nothing changed for agents since the last review: no headless entry point, the matcher still in the TUI (`lib/agendum/tui/commands.ex:386`), no schema for a command's arguments, no golden tasks. The freeze of 2026-10-21 holds the Wol plan and the work towards many users where they are, and the clone does not need them.

Two things I would keep moving, because they protect the clone rather than extend it:

1. **Hostile-text tests.** The clone opens two kinds of outside text today, `.AG` files and, with Extras on, feeds. A test that imports a `.AG` file whose item text asks for changes, and asserts that only its own items appear, is a test of the clone's importer, not an agent feature. I ask that it be counted as clone work.
2. **The Extras switch is also a permission.** When the agent comes, the commands tagged as extras are the first natural scope ("this agent may use the faithful commands only"). Tagging commands now, as ADR 0043 decides, is a small step towards scoped tools, at no extra cost.

**Marie** asked whether golden tasks over `Core.run/3` were frozen too. I think they are, as they test the agent's interface rather than the clone; **Joe** agreed. See § 17.

## § 17 Points of disagreement

1. **A gentler "Overdue" against the truthful clone.** **Russell** has asked twice for a gentler Overdue view in the Planner (`lib/agendum/starters/planner/views.ex:73`). **Mitch** pointed out that the Planner is modelled on Agenda's own PLANNER starter, so changing its tone is not quiet in ADR 0043's sense. Russell accepted that the clone's Planner should match Agenda's, and asked that his recommendation move to a later starter for the easily overwhelmed (VISION's group 3) rather than be dropped. The panel recorded it as such.
2. **Are golden tasks frozen?** **Claude** would keep hostile-text tests moving as clone work (§ 14) and accepts that golden tasks over `Core.run/3` wait. **Marie** and **Joe** agreed on both. **José** would have kept the golden tasks too, as cheap tests of the command layer's design; he was outvoted by no one, since the panel does not vote, and the owner decides.
3. **The date format's default.** **Carsten** favours Agenda's MM/DD/YY as the default with the importer reading a file's own setting (§ 11); **Russell** worried that a Swedish owner's new files would open in a foreign format. Both agreed it belongs in the tagging of the 31 entries, with the owner.
4. **Resolved since the last review:** José and Marie's disagreement on a shelf for general-purpose modules is settled by ADR 0044, which gives the extras a namespace; José agreed that the extras, unlike XML or CP437, are a domain line worth drawing.
