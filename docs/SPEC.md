Rules are numbered so tests and commits can refer to them. ✅ = implemented and tested, ⏳ = planned (see `ROADMAP.md`).

## 1. Concepts

| Concept               | Meaning                                                                                                    | Code                   |
| --------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------- |
| **Item**              | A free-form piece of text (up to a few lines), with an optional note. Exists independently of categories.  | `Agendum.Core.Item`     |
| **Category**          | A named node in one hierarchy rooted at **MAIN**.                                                          | `Agendum.Core.Category` |
| **Link / assignment** | An independent many-to-many link between an item and a category (the patent's "link structures").          | `Agendum.Core.Links`    |
| **View**              | A saved arrangement: **sections** (each headed by a category) and **columns** (each headed by a category). | `Agendum.Core.View`     |
| **Date category**     | Entry, When, Done and ones the user makes: categories whose membership is an item's date.                  | `Database.item_date/3` |

## 2. Data model rules

### Items, categories and the hierarchy

- **R1 ✅ Many-to-many.** An item may be assigned to any number of categories and a category may hold any number of items. Links are reachable from both sides (patent FIG. 2, 3B).
- **R2 ✅ Hierarchy.** Categories form a single tree under MAIN, with ordered children (patent FIG. 1). MAIN, Entry, When and Done cannot be deleted or renamed.
- **R3 ✅ Subsumption.** An item assigned to a category is also a member of every ancestor of that category (patent FIG. 4: I4 in C9 is also in C5, C2, C1). This is computed, not stored.
- **R4 ✅ Deletion side effects.** Deleting a category deletes its subtree and all its links. Items lose the memberships they had only through it (patent: deleting C5 removes I6 from C2 and C1). The category also disappears from view sections and columns.
- **R5 ✅ Every item is in MAIN.**

### Date categories

- **R6 ✅ Date categories.** Entry is set when an item is created, When is read from the item text (R14) or set explicitly in a When column or with ALT-F2, and Done is set by F4.
- **R6a ✅ Date categories the user makes** (User's Guide 6-3, 7-2 to 7-4). Besides Entry, When and Done, any standard category without grandchildren can become a date category (Due, Review, End): Category Properties ▸ Type offers Numeric or Date. Its children whose names are dates ("November 20, 1990", "today") become their items' dates, the others are dropped, and items assigned to the category itself get no date; when items or children are affected, Agenda's question comes first ("Make Review a date category? children become dates; dropped: after the meeting (Y/N)"). Like Agenda, a date category cannot change back, matches no text, and has no children, exclusivity or negative links. Its Category Properties box, like a numeric category's (R29), shows only Category name, Type, Parent, Note, Special actions, Assignment actions, Statistics and Advanced settings, with blank rows where the others were, so the box keeps its size (checked in Agenda 2.0, 2026-10-25: PLANNER's When and Amount, and Calls converted); a short name, Also match words or conditions it had before stay stored but hidden, as Agenda keeps them. Each item has at most one date and time in it, typed in its column ("next friday 3pm"), set in Item Properties or by an action; it makes the item a member, works in sorting, filters and conditions, and is cleared with DEL. Assigning dates automatically (Assign item date, Which one, the Done and When keys) is R6b.
- **R6b ✅ How date categories get dates** (User's Guide 7-5 to 7-8). Category Properties ▸ Date settings opens a date category's Advanced settings box (SPACE/→ next choice, ← previous; each change one undo step). Assign item date: Never; from the clock When item is entered, When item text is edited (also on entry), When note text is edited, When item or note text is edited, When item is assigned (on entry and on joining another category) or When item is assigned or edited; or From the item text, From the note text or From the item or note text. Which one (1–10, for the text choices) takes the nth date: a date and the time next to it count as one, a time alone is today's ("Status meeting from 10:00 to 2:30": When takes 10:00, an End category with Which one 2 takes 2:30). Set the item date from Done key / When key: F4 or ALT-F2 also sets this date (F4 the current date and time, ALT-F2 the When date). Defaults as Agenda's: Entry when entered, When from the item text with the When key, Done never with the Done key, a new date category never; Done always takes the Done key and When the When key. Dates from the clock keep the time, except Entry and Done, which keep the day; Entry always gets the day an item is entered. A date set by hand (typed, Item Properties, ALT-F2, F4) stays when the text changes; dates from text are read once, as for When (R14).

### Exclusion and category links

- **R7 ✅ Mutual exclusion.** A category can declare its children mutually exclusive (e.g. Priority: High/Medium/Low); the category manager brackets such a family's children with ┌ ├ └ ([ for a lone child), as Agenda's. Assigning an item to one child removes it from the others and their subtrees. This applies at every exclusive level above the target. (Patent "negative links", FIG. 6; Agenda's "mutually exclusive" category property.)
- **R7a ✅ Resolving conflicts when making children exclusive.** If items are already in more than one child, the user chooses where they go, as in Agenda 2.0's _Assign conflicting item(s) to_ box (User's Guide, "Resolving conflicts for mutually exclusive categories"): **Parent category** (default; leave all children, assign to the parent), **Existing category** (keep the child closest to the top of the family), or **New category** (a new child, named by the user, gets them). The manual doesn't say where the new category is created; we make it a child so the family stays consistent. Making children non-exclusive keeps all assignments. MAIN and the date categories cannot be made exclusive.
- **R7b ✅ Resolving conflicts when moving categories.** Promoting (F7), demoting (F8) or moving (ALT-F10) a category can put an item in two branches of a mutually exclusive family. The user then chooses, as in Agenda 2.0's _Process conflicting item(s) by_ box (User's Guide, "Resolving Conflicts When Promoting/Demoting Categories"): **Removing from current category** (default; the moved category), **Removing from conflicting category** (the branch it clashes with), or **Moving to new category** (named by the user). We create the new category as a child of the exclusive family where the clash happens, and the items leave both clashing branches. Reordering siblings cannot clash.
- **R7c ✅ No direct assignment to both a category and its ancestor.** An item is a member of every ancestor through inheritance, so it is never _directly_ assigned to a category and one of its ancestors. Assigning to an ancestor breaks the item's assignments to its descendants (as the manual states, User's Guide 16-5). Assigning to a descendant replaces a direct assignment to an ancestor (our reading of "does not let you assign... to both"). Automatic assignment never assigns a category the item already belongs to, and when a category and its ancestor both match the text it keeps the more specific one. A category link (`also_assign`) to a category the item already belongs to is skipped. A move (promote, demote, ALT-F10) that would break the rule offers the same three choices as R7b; when it breaks both rules, we show one box for both instead of Agenda's two boxes in sequence. With "Moving to new category", the new category is created under the conflicting ancestor or exclusive family.
- **R7d ✅ Outline-style promote.** The hierarchy behaves like an outline whose order never changes; promote and demote only shift a category's level (User's Guide, "Promoting and Demoting Categories"). Promote moves a category up one level, right after its old parent, and its following siblings become its children, after its own children (Figure 16-13: promoting Sam adopts John and Anna, and Sam's child Ted comes along). Demote makes a category the last child of its previous sibling and is refused for a first child, which would skip a level. Conflicts caused by adopted siblings (Figure 16-15: promoting Anna makes Tim its child) are resolved with the R7b/R7c choices; when several links clash, the one closest to the top of the outline wins. Our reading: the promoted category keeps its own subtree, which matches the manual's example.
- **R8 ✅ Category links.** A category can pass its items on to other categories (`also_assign`, patent FIG. 6). This applies transitively and is safe with cycles.
- **R9 ✅ General negative links** (not in Agenda 2.0; the patent's negative links, FIG. 6, which Agenda only offered between siblings as R7). Category Properties ▸ Excludes opens a category list in which SPACE toggles a negative link (marked "x") between the two categories: no item may then be in both, or in their subcategories. Assigning an item to one (or below it), directly, by a category link or by an action, takes it out of the other and its subcategories; text matching never puts an item in both, and an assignment the item has wins over a new text match. The link is kept on both categories, shown in Category Properties ▸ Excludes, and dropped when either is discarded. It is refused between a category and itself, its parents or children, MAIN and date or numeric categories, and while items are in both ("2 items are in both Work and Vacation; move them first"); a category cannot be moved under one it excludes.

### Dependencies

- **R43 ✅ Item dependencies** (User's Guide 13-12 to 13-16; Lotus Q&A "Hiding Done and Dependent Items"). ALT-O makes the current item depend on the marked items (its prerequisites), after a Y/N question, adding to any it has; with nothing marked, ALT-O on a dependent item offers to clear its dependencies. An item cannot depend on itself, even through others. While a prerequisite is not done the item waits, shown with "&"; discarding a prerequisite drops it. View Properties ▸ Hide dependent items (R78; "[Hide dependent]" beside the view's name) hides waiting items until every prerequisite is done or discarded, also when done items are hidden too (the Q&A's bug). Item Properties lists by name the items it depends on ("Depends on") and those depending on it ("Needed by"), done ones marked ‼; SPACE on one opens its Item Properties (ESC comes back), DEL removes that one dependency. As in Agenda, a dependent item can still be marked done or discarded first. Utilities ▸ Show ▸ Depends and Prereqs (Agenda's) list, in the Show View, the items depending on the highlighted one or the items it depends on: One level, All levels (the whole chain), or Every item in the file that has dependents (or prerequisites); ALT-F8 returns.

## 3. Automatic assignment

### Matching item text to categories

- **R10 ✅ Text matching.** When an item is entered or edited, it is assigned to every category whose name (or short name) appears in its text as whole words, ignoring case and extra whitespace (patent: "Meet with John Smith on Tuesday" → Meetings + John Smith). Categories can opt out (`match_name: false`).
- **R11 ✅ Explicit wins.** An automatic match that conflicts with an existing explicit assignment (R7) is dropped.
- **R12 ✅ Ambiguity (patent claim 7).** If two matches conflict with each other, prefer the category that the adjacent item in the view belongs to (previous, then next). Otherwise prefer the category created first.
- **R13 ✅ Recalc.** The user can re-run automatic assignment for all items (Recalc, with CTRL-X: Agenda had no such command, so it has neither a key nor a menu entry).

### Dates read from text

- **R14 ✅ When dates from item text.** The first date in an item's text becomes its When date ("Call Toni on August 7", "Cheryl arrives tomorrow"); items with no date get none (User's Guide 6-6 to 6-7). Editing the date words changes the When date; relative dates are read once, so editing other words keeps it, and removing the date words clears it. A When date set explicitly (When column, ALT-F2) overrides the text, and later edits leave it alone; clearing it (DEL in the When column) hands it back to the text. Setting the When category's Assign item date to Never (R6b) turns automatic dating off for a file, shown as `[No Auto Dates]`. Recalc dates items that have a date in their text but no When date. Dates follow the manual's rules (chapter 7): weeks run Monday to Friday; a bare weekday is its next occurrence (today if today); this/next/last put a weekday in the current, following or previous week; this/next/last week/month/year is the start of that period; a date without a year is in the future. Supported phrases: today, tomorrow, yesterday (and Agenda's "tmorrow", "ystday"), the day after tomorrow / before yesterday, weekdays, beginning/end of a week or month, in N days/weeks/months (digits or words), N … from today, N … ago, a fortnight, month-day dates ("August 7", "November 23rd, 1991", "the first of November", "7 Aug"), and numeric dates (11/20/90, 11/20, 2026-11-20). Times ("at 3:00") are accepted and ignored. Our safeguard: bare abbreviations that are common words ("sat", "sun", "wed", "may" alone) count as dates in item text only after "on", "by", "until" or "till", or with a day number ("May 5").
- **R14b ✅ Times of day** (User's Guide 6-12 to 6-13). When dates can carry a time, read from item text or typed into a When column / ALT-F2: "3:30 pm", "@ 3pm", "15:30", "noon", "morning" (8:00), "afternoon" (14:00), "evening" and "tonight" (17:00), "now", "in 2 hours", "45 mins from now". A time alone means today; a time without am/pm falls between 8:00 am and 7:59 pm ("3:30" is 15:30); hours over 12 and a leading zero read as a 24-hour clock. When columns show "2026-10-13 15:00" and sort by date and time. A time never reuses a date's words ("at 12/24").
- **R14c ✅ Date languages** (not in Agenda). Dates and times can be typed in another language than English, chosen in Utilities ▸ Customize (Date language, Fallback language; saved in the person's preferences, R41b) or for one session with `--lang=swedish`, with an optional second language, `--fallback=english`, whose phrases are read as well (where both match the same words, the main language wins; without a fallback only the main language and ISO dates are read). It applies to every date typed: item text, date columns, the When prompt and date filters. Nothing else changes: menus, messages and how dates are shown stay as they are, and the file does not record the language. Phrases kept in the file and read again each time (a date filter's ends, a datebook's base date, a date action's date) are read in the person's languages and then in English, so a file made in English, such as a starter file, works in every language (ADR 0029). Each language is a pack (`Agendum.Core.DateLanguage`): its words, phrase patterns, day/month order and clock. Swedish reads weekdays ("fredag", "på fre", "nästa fredag", "förra måndagen", "i fredags" = the latest past Friday), days ("idag", "i morgon", "i övermorgon", "i går", "i förrgår"), "den 5 november", "5:e nov", "den femte november", "5/11" as day/month, "om två dagar", "för 3 veckor sedan", "nästa vecka", "i slutet av månaden", times on a 24-hour clock ("kl 15", "kl. 9.30", "15:30"), "förmiddag", "eftermiddag", "i kväll", "om 2 timmar", and recurring dates ("varje måndag", R14a). Bare abbreviations ("fre", "sön") count in item text only after "på", "till" or "senast" ("tor" not at all, being a name); "nu" and a lone "morgon" are not read.
- **R14a ✅ Recurring dates** (User's Guide 6-10, 7-11 to 7-12). A date with "each", "every" or "evry" recurs: "every Monday", "every other Monday", "every day", "every 2 weeks", "every month", "every quarter", "every three months", "every year", "the 30th of every month", "the fifteenth of each month" (Swedish: "varje måndag", "varannan fredag", "var tredje månad", "varje kvartal", "den 15:e varje månad"). The first date is the base date: the next such weekday (today if it is today), the day of the month this month or next, or today for the others. The item keeps the rule (`Item.recurrence`, language-neutral), read from its text or typed into the When column / ALT-F2; an explicit plain When date, or an edit that removes the phrase, ends it. Marking a recurring item done (F4, the profile's Done, or bulk done) dates it done and adds a copy right after it: same text, note, time, alarm and assignments, with the next date counted from the base date; months keep their day (the 30th falls on the 28th in February and on the 30th again in March), so the cases Agenda 2.0 got wrong in Lotus's support Q&A (the 30th drifting, "every quarter" as every six months, "every three months" as two) come out right. Item Properties shows the rule ("When (2026-10-12) · every Monday"), and F4 says when the next one is. A recurring item shows on every date it recurs, counted from its base date and never before it, as Agenda's (checked in Agenda 2.0, 2026-10-15 and 2026-10-23): in each datebook slot that holds an occurrence (once per slot, ordered by that occurrence and in the slot of its time; an End category's span moves with it), and in a view or section whose When range filter holds one (outside the range means none does). It stays one item: F4, discard or a move on any of its rows acts on it, and F4 on a later occurrence marks it done and adds the next after its base date, as on the base date (Agenda the same). Its When column shows the occurrence it is listed for: the slot's, or the first from the start of the When range; elsewhere its base date. Our choice: a done item keeps its rule stored (marking it not done again brings it back) but counts only on its own date, where Agenda's F4 leaves it a plain date. Editing the date (ALT-F2, F2 in the When column) offers the rule with its base date and time in the reader's language, `every Monday (starting 2026-10-19) at 9:00am` (Swedish `varje måndag (från 2026-10-19) kl 09:00`), as Agenda's ALT-F2 offers `every Mon (strtng 10/19/2026) at 9:00am` (checked 2026-10-23), so ENTER keeps it; reading it back takes the bracket's date as the base, moved on to the rule's next day when it is not one ("every Monday (starting 2026-10-20)" is the 26th), and Agenda's own "(strtng …)" is read too. Our choices: the words written out and the date as ISO 8601, as every date offered for editing; a rule the reader's language has no words for ("var tredje måndag" in English) is offered as its date alone, as before. Not done: the "Can use recurring dates" property of date categories (only When recurs).
- **R14d ✅ More date phrases** (User's Guide 6-7, 6-10 to 6-11, 7-16). Working days ("in five working days", "3 working days ago") skip Saturday and Sunday. Quarters ("this/next/last quarter", "end of the quarter", "first quarter"; the first to fourth quarter is this year's unless it has ended) and years ("end of the year"). The nth or last weekday of a month ("first Wednesday in November", put in the future like other dates without a year; "the last Friday of the month", "second Monday of next month") and a day of a month ("the 15th of next month"). A month alone means its first day: on its own ("April") it is this year's unless the month is over, "this April" this year's, "next April" the first after this month, "last April" the last before it; "end of next March" is its last day. In item text a month alone counts only after "next", "last", "this", "in", "by", "until" or "during" ("May" only after "next" or "last"; in Swedish only full names, so "i jul" stays Christmas). Calendar notation can use a month abbreviation ("Nov/12/90"). Swedish has the same phrases ("om fem arbetsdagar", "första onsdagen i november", "i slutet av nästa mars").
- **R14e ✅ Global date settings** (User's Guide 7-13 to 7-17). File Properties ▸ Global date settings opens Agenda's Global Date Settings box (boxes nest as in Agenda: File Properties holds Global date settings ... and Auto-assign settings ...; Global Date Settings holds Display format ..., Input format ... and the settings below; SPACE or → opens a "..." row, ESC goes back one box), saved in the file: Beginning and End of week (Mon and Fri: "this week" and "next week" start on the first day, "end of week" is the last, "this Monday" is in that week, and working days are the days from the first to the last); First quarter (the month quarters start in, Jan); Beginning of year (the month "this year" starts in, Jan; the year ends the day before the next one starts); Month alone means (First day, Last day or Day 2–31, a short month's last day if it has fewer); and the times of Morning (8:00), Afternoon (14:00) and Evening (17:00, also "tonight"). Morning also starts the twelve hours that times without am/pm fall in (with 9:00, "at 8:00" is 8 pm). Settled differently from Agenda: number order stays with the reader's date language (R14c, ADR 0009), not the file; quarters and years start on the 1st of a month; Agenda's separate End of year is the day before the next Beginning of year. The settings apply to dates read from then on, and to relative dates in filters and conditions, which are read anew.
- **R14f ✅ Fixed relative dates and dates from notes** (User's Guide 6-7, 7-6 to 7-7, 7-11). A "$" before a relative date in a date range of a filter or condition ("$Monday", "$ end of next week") reads it once, when the range is set, and keeps that date (shown as a date from then on); without "$" the words are read again each day. When's Assign item date (R6b) says where When dates are read from: From the item text (default), the note text, the item or note text (the item's first, else the note's) or Never (what Utilities ▸ Dating toggles). A note's date is read when the note is saved, by the same rules as item text (read once; removing it clears the date; a date set by hand stays).

### Conditions and actions

- **R15 ✅ Assignment conditions** (User's Guide, chapters 18 and 20). A category can have conditions on other categories: items *assigned* to them (Urgent if Taxes and Accountant) or *not assigned* to them (Me if not People). All conditions must hold, except "assigned" conditions on mutually exclusive categories, which are alternatives (High or Low). Agenda checks an item against all conditions when it is added, edited, assigned or unassigned: a category whose conditions it meets assigns it, and an assignment a condition made is broken once the condition no longer holds. Assignments the user makes are never broken by conditions. Like Agenda, a new condition applies to existing items only after Recalc (Agenda's Utilities Execute). Conditions are set in category properties (ENTER on a category cycles none → assigned → not assigned); Category Properties shows them ("if Taxes, not People"; the category manager would with Agenda's Customize ▸ Display cond/act info, not built) and the assignment profile marks conditional assignments with "c". Contradictory conditions settle after a bounded number of rounds. Only a standard category's conditions assign: a category made a date or numeric category keeps its conditions in the file, but they assign nothing, not even on Execute (checked in Agenda 2.0, 2026-10-16: its box offers Assignment conditions "Only if Type is Standard", and the stored ones have no effect).
- **R15a ✅ Date and numeric conditions** (User's Guide 20-5 to 20-7). A category's conditions can name a date or numeric category: choosing one in the conditions box opens the Date Condition or Numeric Condition box (the filter box of R28a): Show items (Assigned, Not assigned = without a date or number), Start and End date (or Minimum and Maximum; blank ends are open, both blank means any), Inside or Outside range. Items in the range are assigned conditionally and let go when they leave it, when their date or number changes, and, for relative dates ("beginning of this week" to "end of this week"), when the date changes: the clock tick re-checks every item on a new day. Dates are read in the reader's date languages (R14c). A category cannot have a condition on itself. The condition shows like a filter ("if When 2026-10-05..2026-10-09").
- **R15d ✅ Text conditions** (User's Guide 19-2 to 19-5). Category Properties ▸ Also match holds words and phrases that pull items into the category as its name does: `;` separates alternatives (any), `,` conditions that must all hold; a word or phrase matches when its words are there, in any order, by the file's matching settings (R16a), and in parentheses only in that order (`(meet with)`); `^` matches its words as they are, ignoring no suffixes (`^eats`); `!` before one means the item must not contain it (`Cost,!Deduction`), `~` that case must match (`~LOTS`); `?` is one character and `*` any characters within a word (`Budget??`, `sl*`); `\` makes the next character plain text. Text conditions work even when the category does not match its own name. New ones reach existing items with Recalc. Not done: Agenda's `"` (exclude words).
- **R15b ✅ Actions** (User's Guide chapter 21). When an item joins a category, by the user, a condition or another action, the category's actions run once: Category Properties ▸ Assignment actions lists them ("Sales, -Receivables, When=tomorrow, Amount=150"); in its box ENTER on a category cycles assign (a category link, R8) → remove (break the item's assignment there) → none, and a date or numeric category opens the Date / Numeric Action box: give items a date (an expression read when the action runs, in the reader's languages) or a number, or remove it. Special action: None ("No action" in the box, as Agenda), Mark items done (today, recurring items get their next one) or Discard items. A parent's actions also run for items that join its children, children's first; special actions run last. Actions make explicit assignments, which stay when the triggering one is broken, and do not run again when an item changes while it stays in the category. Not done: the Export special action (with structured files, Milestone 4) and turning actions off per category or file.
- **R15e ✅ Utilities Execute** (User's Guide 20-19 to 20-21, 21-17). New conditions, text conditions and actions do not reach items already in the file until executed. Utilities ▸ Execute opens the Execute box: Apply conditions attached to category and children of (a category and its children; MAIN for all; two lines, as Agenda's), Against (all items, the current item, the marked items, the items in the section or the view) and Apply actions to (new assignments only, or old & new: the actions also run for assignments the items already had). ALT-X executes everything on all items; ALT-E the highlighted category's family (in a view: the section's category). Recalc (CTRL-X) still re-runs automatic assignment and dating for every item.
- **R15f ✅ Copy and clear conditions and actions** (Agenda's ALT-F9 CPY C/A and ALT-F8 CLR C/A in the category manager; Help "Copy Conditions/Actions", "Copy Conditions/Actions Box", "Clear Conditions/Actions Box"; checked in Agenda 2.0, 2026-10-26; found missing while writing the help). ALT-F9 on a category with conditions or actions asks on the top line, as Agenda's, "Move cursor to the category you want to copy to" (the second line blank): the arrows move, ENTER copies to the highlighted category, ESC gives it up. A source with only conditions (or only actions) copies them at once, without a word; one with both asks first in Agenda's untitled box, "Copy:" Condition & action (first), Condition or Action. What is copied takes the place of the target's conditions or actions; the other kind and the source stay as they were. ALT-F8 asks "Clear the condition?" (or "the action?") when the category has one kind, and with both Agenda's box, "Clear:" Condition & action, Condition or Action. With nothing to copy or clear nothing happens, as in Agenda. Conditions are the category's assignment conditions; actions its assignment actions (links to other categories, and dates or numbers); Also match words do not count (Agenda copied nothing from a category with Also match alone). Each copy or clear is one undo step, where Agenda's could not be taken back. Like a new condition, a copy reaches the items already in the file when executed (R15e). Our choices: a condition or action naming the target itself is left out of the copy (a category cannot have one on itself); copying to the source says "Choose another category to copy to". Unchecked: whether Agenda copies the special action too (ours does not).

### Suggestions, text matching settings and reasons

- **R16 ✅ Suggested assignments** (User's Guide 19-9, 19-12). File Properties ▸ Auto-assign settings ▸ Confirm assignments: Never (the default; text matches are assigned at once), Always, or Sometimes (only partial matches, R16a, are suggested; full ones are made). Suggested: an item's text matches become suggestions instead, "?" shows in the title while any wait, and Utilities ▸ Questions (Agenda's) shows each such item in turn with its suggested categories: SPACE picks one, TAB all, ENTER assigns the picked ones (explicitly, so an edit does not take them away) and goes to the next item, ESC stops. The box is drawn as Agenda's Questions box (checked in Agenda 2.0, 2026-10-25): 'Suggested categories for "the item"', each category as Parent:Child (one right under MAIN by its name) with ? before it, * once picked, and "Press ENTER to accept"; with none waiting, a box says "There are no assignments to be confirmed." and any key closes it. Editing an item asks again about what its new text matches; discarding the item or the category drops the question.
- **R16a ✅ Text matching settings** (User's Guide 19-7 to 19-12, 19-15 to 19-16). File Properties ▸ Auto-assign settings opens Agenda's Auto-assign Global Settings box (SPACE/→ next choice, ← previous; each change one undo step): Text matching On/Off (Off: no names or text conditions match); Match on Item text (default), Note text or Both item & note (a note is matched when saved, and a match from it breaks when it stops matching, R15c); Required match strength: Exact match - 100% (default; every word of a name, short name or text condition, in any order), Partial match - 50% (at least half) or Minimal match (one word), as in the manual's "Suggestions for design"; Confirm assignments (R16); Ignore item text enclosed by: " " (default, also “ ”), < >, ' ', { }, [ ], # #, ( ), / /: that text is left out ('set a "margin" command' does not go to Margin); Ignore suffixes Yes (default): -able, -al, -ly, -ally, -d, -ed, -er, -est, -ible, -ing, -ment, -s, -es, -wise, and for words ending in y -ied, -ier, -ies, -iful, -ily, so Show matches shows, showing and showed; words of three letters or fewer match exactly ("buy" is not "buying"); Ignore accents No (default; Yes: résumé matches resume). Words are read as Agenda does: a word starts with a letter or digit and may hold ' - _ ("can't", "high-capacity"); a possessive 's is dropped. A text condition in parentheses must have its words in that order ("(meet with)"), and "^" before one matches its words as they are, ignoring no suffixes ("^eats"). A name with other characters ("C++") matches as written. Proper names and titles: R16c.
- **R16b ✅ Text matching for one category** (User's Guide 19-8, 19-14 to 19-15). Category Properties ▸ Advanced settings of a standard category (for a date category it holds R6b's date settings) sets Text matching, Match on, Required match strength, Confirm assignments, Ignore suffixes and Ignore accents for that category only; each is Global (the file's, shown in brackets: "Global (Item text)") until set, and cycles back to Global. Ignore text enclosed by is the file's only. A category matches with its own settings (Budget on the note while others match the item text), suggests or assigns by its own Confirm assignments, and its Advanced settings row sums it up ("Match on: Note text"); Agenda's "T= Note" in the category manager shows only with Customize ▸ Display cond/act info, not built. The row sums up what the category sets ("Match on: Note text") or says Global.
- **R16c ✅ Proper names and titles** (User's Guide 19-17). A category name or short name with two or more consecutive capitalized words holds a proper name ("Nancy Wohl"; hence the manual's advice to write "Status report", not "Status Report"). The name matches when the text has its last name, exactly (no suffixes ignored), alone ("Send it to Wohl"), after a title ("Mrs. Wohl") or after one of its own first names, but not after another capitalized word ("John Wohl" is someone else) and not on the first name alone; a capitalized word starting the text or a sentence does not count ("Call Wohl"). Required match strength does not apply to the name; other words of the category name match as usual ("visit Nancy Wohl" matches "Visiting Mrs. Wohl"). Titles, with or without a period: Mr, Ms, Miss, Mrs, Messrs, Dr, M, MM, Monsieur, Madame, Mme, Mmes, Mademoiselle, Mlle, Mlles, Herr, Hr, Frau, Fr, Fräulein, Fri, Fru, Fröken, Frk. "Michael Schaeffer" in an item matches Michael, Schaeffer and Michael Schaeffer, not Michael Rowles.
- **R67 ✅ Why an item is in a category** (not in Agenda; for the Questions box, help on an assignment and an agent's report). The core says why an item is in a category (`Agendum.Core.assignment_reasons/4`), from the file as it is and the same rules that assign: MAIN (R5), a date in a date category (R6), through a child it is in (R3), the category's conditions (R15, read with the clock), its text matching the category's name or Also match words (R10), an action of another category it is in (R15b), or else by hand (or kept from before). The file does not keep who made a link, so a text match is given whenever the text matches, whether the match or the person assigned it first. The assignment profile (F3 on an item) says it in the control panel for the highlighted category, as "In Urgent: its condition holds (Calls)" (owner, 2026-10-16); a message comes first, and a category the item is not in adds nothing.
- **R15c ✅ Text matches as conditional assignments** (User's Guide 18-3). An assignment made because the item's text matched a category (its name, short name or text conditions) is conditional, marked "(c)" in Item Properties, and is broken when the text no longer matches and no other condition holds ("Meet with John" in Meetings; edited to "Telephone John", it leaves). An assignment the user makes is explicit and stays.

## 4. Working through views

All modification happens in the context of a view (patent claims 1, 3, 4, 6).

### Sections and items

- **R20 ✅ Sections.** A section lists every item that is a member of its head category (including via subcategories), in item order. Items that are members only through a subcategory are "inherited" and can be hidden.
- **R21 ✅ Entering an item.** Typing under a section creates an item assigned to the section's category (unless it is MAIN), placed after the highlighted item. Automatic assignment (R10–R12) then runs, using the neighbouring items in the section for R12.
- **R24 ✅ DEL** on an item removes it from the section's category (and its subtree), after Agenda's question (checked in Agenda 2.0, 2026-10-25; the owner's choice): "Remove this item from the section?  Yes", with "(Use ALT-F4 to discard the item completely.)" under it; ENTER removes, ESC keeps, and with Confirm off (R54) it removes at once. The item stays in the file. On a column entry DEL unassigns it, and on a section head DEL removes the section from the view. **DISCARD** (ALT-F4) deletes the item from the file, into the trash (R24a).
- **R24a ✅ The trash** (User's Guide 3-4 to 3-5, 13-18 to 13-19; checked in Agenda 2.0, 2026-10-26; the owner's choices, all as Agenda's). A discarded item (ALT-F4, Item ▸ Discard, a category whose special action discards, R15b) leaves the file for the trash, without its assignments: its categories, values, When and Done dates and alarm go; its text, note, Entry date and Zettel id stay. **Item ▸ Undisc** brings items back into the highlighted section, below the highlighted item (on a section head, in their usual place), assigned to the section's head alone, and their conditions and actions run, as in Agenda: an item undiscarded there came back without its date. With one item in the trash it comes back at once; with several, Agenda's box asks "Undiscard:" All items in trash (first) or Last item in trash, and they come back newest first; with none, Agenda's "There are no discarded items in the trash, so there are no items to recover." **Utilities ▸ Trash** asks "Empty the trash?" (with none, "There are no discarded items in the trash, so there is no trash to empty."); its items are then gone for good. **File Properties ▸ Empty trash** says when it also empties by itself: On demand, When file is closed (the next time the file is opened, here), End of day (the default, for every file: once the day the oldest item was discarded is over, while Agendum runs or when the file is next opened) or When item is discarded (no trash at all; our choice: the items already in it stay until it is next emptied, where Agenda emptied it when the box was accepted). File statistics counts the items in the trash. The trash is saved with the file. Emptying is not an undo step; a discard and an Undisc are. Agenda 2.0 does not ask DEL's other question, "Item has no other assignments. Discard the item?": every item keeps its Entry date (checked, 2026-10-26). ALT-Y stays DEL's yank (R42): after a discard it did nothing in Agenda 2.0, though its help says it recovers the latest one.
- **R25 ✅ Editing the structure from a view.** Rename a category by editing a section head or column entry (F2). Add sections (ALT-D/ALT-U) and columns (ALT-R/ALT-L) with existing or new categories.
- **R26 ✅ Move (ALT-F10).** Moving an item to another section reassigns it from the old section's category to the new one and reorders it.
- **R27 ✅ View options.** Hide done items, empty sections, inherited items: set in View Properties (R78), as Agenda's; the menus have no shortcut entries for them (nor for the view's filter and sort, a section's filter, sort, collapse and lines, or the view and category managers, which are F8 and F9), as Agenda's had none.
- **R58 ✅ Section separators** (User's Guide 5-12, 15-21; screenshots 48, 54, 143). A view setting, No by default: with Yes, each section head is a line across the screen, the section's name and its column heads on it, in place of the blank line before the section, so more fits on the screen. The highlight on a section head covers its name only. Set with View Properties ▸ Section separators (R78; in a datebook view its settings box), one undo step. With Hide column heads (R57), the other section heads are their names on a plain line. Our choices: a datebook view's slots are lines either way (R47); File ▸ Print to a file has no lines, as Agenda printed none ("The lines between sections do not appear when you print").
- **R59 ✅ The note symbol and NOTE for what is highlighted** (User's Guide 12-2 to 12-4; screenshot 126). In a view, ♪ at the right of the control panel's second line shows that what the highlight is on has a note: the item, the section head's category, a column head's category, or the category a column entry stands for, the first the entry shows (a Star or Yes/No entry: the head, when the item is in it). A date or a number is no category, so it has no note. NOTE (F5) opens that note: in a column, the column head's or the entry's category's (Agenda: "Highlight the item or category"), where it used to open the item's; on a date, number or empty entry it says Agenda's "The highlight isn't on a category.  Highlight the category you want and repeat the command." The rows show notes too, as Agenda's (checked in Agenda 2.0, 2026-10-25): a section head's first column holds ♪ when its category has a note (a space otherwise), and an item's row is four spaces, its tag (♪ in the bullet's place for an item with a note; ‼ done, & waiting, @ alarm before it; ‼ is Agenda's, Help "View Indicators"), its mark (♦ when marked, a space otherwise; a marked item without another tag has ♦ in the bullet's place, `    ♦ Call Bob`, as Agenda's) and its text from the seventh column, wrapped lines too. The highlighted row shows », as Agenda's: on the item text the highlight covers the text (as wide as its longest line) and » stands in the space before the first column right of it; on a column entry » takes the bullet's place (an item with another tag keeps it; seen for ♪). A filled column entry has · before it, as Agenda's (Help "View Indicators": the item is assigned to, or inherits, the column's head), dates and note lines too but not numbers; the highlighted row's first one is », the item text being highlighted.
- **R61 ✅ Section Properties** (Help "Section Properties/Add Box"; User's Guide 5-5 to 5-10). One section's settings in one box, opened with View ▸ Section ▸ Properties or F6 (PROPS) on a section head, as in Agenda (F6 on a section head used to open the head category's properties; F6 on the box's Section head does that now). Section head: a typed name (a new category if no category has it) or F3 picks one; Item sorting opens the section's sort (R36); Section statistics says how many items the section shows; Select numeric functions (only in a section with a numeric column; User's Guide 8-10) opens a box of Count, Total, Average, Minimum and Maximum, Yes or No, for every numeric column of the section at once: they are the columns' own calculations (R29), so a linked column changes in its other sections too, and a function shows Yes when every numeric column has it; Filter opens the section's filter (R28); Columns lists the section's columns in their order with the item column as `<Items>`: DEL removes a column from this section only (the item column stays), ALT-↑ ↓ move a column or the item column (Agenda: ALT-F10), INS adds a column right of the highlighted one (Column Add, R55). Not in a datebook view, whose sections are its dates (R47). **Section Add** (View ▸ Section ▸ Add; Agenda's, checked in Agenda 2.0, 2026-10-24; the owner's choice) is the same box, titled Section Add, opened blank with Insert under the head: Below current section (the default) or Above current section, SPACE switches it. Once the head is typed (a new category under MAIN when no category has the name) or picked with F3, the section is added there, with the linked columns of the current section (R55), and the box goes on as its settings; switching Insert then moves it to the other side of the current section. ENTER before a head adds nothing and says what is needed, as Agenda's box does not close; ESC takes everything back, the new section included. ALT-D and ALT-U still add a section below or above at once, with the category picker.
- **R62 ✅ Moving a section** (User's Guide 5-8 to 5-9). ALT-F10 (MOVE) on a section head, or View ▸ Section ▸ Move from anywhere in a section, moves it within its view: every section is shown collapsed (§ and its item count), ↑ ↓ (or < >) move it, ENTER keeps the new place (one undo step; the sections open again) and ESC puts it back. Only this view changes, not the category hierarchy. The file is not changed while it moves (ADR 0026). Our choices: a view that sorts its sections (View Properties ▸ Section sorting) says so instead, as the sort would put the section back; a datebook view's sections are its dates (R47).
- **R78 ✅ View Properties** (User's Guide 9-9 to 9-11; Help "View Properties/Add/Copy Box"; screenshot 143; checked in Agenda 2.0, 2026-10-23). A standard view's settings in one box, opened with View ▸ Properties or F6 (PROPS) on a view in the view manager, as Agenda's; F6 in a view still opens the properties of the item, section or column highlighted. A datebook view's View ▸ Properties and F6 open its datebook settings (R47). Laid out as Agenda's: on the left View name (typing replaces it, F2 edits it), Item sorting (the view's sort, R36), Section sorting (None, Category order, Alphabetic, Numeric) with Order (Ascending, Descending) under it while it is not None, Hide empty sections, Hide done items, Hide dependent items, Hide inherited items (R27), Hide column heads (R57), Section separators (R58), Number items (R79, on the row of Filter), and View statistics (a box of the marked items the view shows, its sections, empty ones too, and the items its sections show, an item in two sections counted twice; any key closes it, as Agenda's); on the right Sections, the view's sections in their order, and Filter under them (R28). In Sections ↓ and ↑ walk the sections, ↓ from the last goes on to Filter and ↑ from Filter to the first (as Agenda's); typing a name or INS adds a section below the highlighted one with its linked columns (R55; a new category under MAIN when no category has the name); F3 opens Agenda's Section Select (User's Guide 9-8, 9-11; checked in Agenda 2.0, 2026-10-25; the owner's choice): "Current View:" and the hierarchy, * on the view's section heads, SPACE (F7 INCLCAT) making a category a section (at the end, with the last section's linked columns) or no longer one, F5 (CHLDRN) a parent's children instead of the parent, F4 (CLRCATS) none, ENTER or ESC going back keeping it (R81b), the top line saying Agenda's "Highlight each category for the section head(s) and press SPACE BAR. A view setting, No by default, set with View Properties ▸ Number items (R78; in a datebook view its settings box, as Agenda's), one undo step; its control-panel line is Agenda's, "Display a number next to the item tag in front of every item." ### Columns

- **R22 ✅ Columns (claim 2).** A column headed by category _C_ shows, for each item, the descendants of _C_ the item is assigned to. A childless head shows `*` when the item is a member. A date column shows the date. When a column is too narrow for a category's full name, the category's short name is shown instead, for column entries and column heads alike (User's Guide 19-2). Each section has its own columns (R55).
- **R22a ✅ Fit column to contents** (Agenda's SHIFT-? in View ▸ Column ▸ Width, User's Guide 5-21). SHIFT-? while choosing a width sets the highlighted column's width to the widest of its head and the entries of the items the view shows at that moment (collapsed sections left out), with full names rather than short ones and its calculation lines; at least 3, at most 80. It is done once: the width does not follow later changes. One undo step. A linked column (R55) fits the entries of every section it is in.
- **R23 ✅ Typing in a column (claims 3, 6).** Text typed in a column cell is matched against the column head's descendants with automatic completion (R32); if nothing matches, a new child is created. Typing replaces the current entry; INS adds another one. Date columns parse dates.
- **R55 ✅ Columns per section** (User's Guide 3-16, 3-27, 5-22 to 5-25; screenshots 42, 60, 127). A column belongs to one section or to all.
  - Added to all sections (the default), it is *linked*: one column shown in several sections, so changing its width or format in one changes all of them. Added to one section, it is not linked and changes alone. Each column added is a column of its own, even with the head of another: a section can show When twice, and removing or widening one leaves the other alone (as Agenda does, checked in DOSBox).
  - View ▸ Column ▸ Move, or ALT-F10 on a column head (User's Guide 5-20): ← → (or < >) move the highlighted column in its section, shown at once; ENTER keeps the place (one undo step), ESC puts it back. Only the current section changes, even for a linked column, which stays linked. On the item text it moves the item column among the columns (not in a datebook view, whose item text stays first): the columns left of it are drawn before the bullet, and → ← go through the columns as they are shown. A column added right or left of the item text or of a column (ALT-R, ALT-L, the Column Add box) lands there, and the item column keeps its place when columns are added or removed.
  - Where the other sections get it (ours; Agenda does not say): beside the same column as where it was added (after the column on its left, or else before the one on its right), at the end when the section has neither: in a section with two of that head, beside the one linked to it.
  - Removing a column that is linked into other sections asks: *All sections in view* (it goes from every section it is in; other columns of the same head stay) or *Current section only*.
  - A new section (ALT-D, ALT-U) gets the linked columns of the section the cursor was in (ours).
  - Each section's item text fills the width its own columns leave, so a column every section has stays in the same place (screenshots 42, 60).
  - Item Column Properties (View ▸ Column ▸ Properties on the item text; User's Guide 3-18 to 3-19, Help "Item Column Properties Box"): the Section head (F3 picks another); Width, the item text's width now (typing one sets it by hand, as Agenda's, checked 2026-10-25); Set width Automatically (the default: as wide as the section's columns leave, at least Minimum width, 10) or Manually (Width, the columns following right after it; Manually starts at the width the text has then); Link with other sections (Yes by default): linked item columns change together, No makes one change alone, Yes again takes the linked ones' settings. Widths 5 to 200 (Agenda: 77, its screen). A new section gets the linked ones' settings. Each change is one undo step. A datebook view's item text always fills what its columns leave.
  - A datebook view's slots share one set of columns (R47).
  - Files from before this keep every column in every section, linked. Files that marked columns only as linked (formats 25, 26) get one column for the first linked column of a head in each section, another for the second, and so on.
  - File Properties ▸ Insert new columns in (screenshots 130, 131): All sections (the default) or Current section, for the file; it decides where ALT-R and ALT-L put a new column.
  - A new column is 16 wide for a date category (a date and a time), 12 for others.
  - Column Properties ▸ Link with other sections (screenshot 127): No unlinks the column, which changes alone from then on. Yes links it to a linked column of its head that is not yet in its section, taking its width and formats; when there is none, to an unlinked column of its head with the same width and formats in each other section (Agenda: "the same column head, category type, format, and width"). Yes on a linked column changes nothing.
  - Column Properties ▸ Column head (screenshot 144): F3 (or SPACE) picks another category from the whole hierarchy; the column and the columns linked to it show it instead, staying a column of their own; an unlinked one changes alone.
  - Typing on Column head, in Column Properties or the Column Add box (User's Guide 3-17: "the name of a new or existing category"), gives the category of that name, case aside, or a new one under MAIN; a name several categories have is left to F3. ESC drops the name. In Column Properties the head changes with it, one undo step; in Column Add a new category is made at once and the column waits for ENTER.
  - The column heads on a section head line can be highlighted (→ / TAB, User's Guide 5-22, 5-25), so an empty section's columns can be reached: DEL removes the column (asking which sections, as above), F3 replaces the column head, F6 opens Column Properties, and F2 renames the head's category (ours; the manual does not say).

- **R56 ✅ Standard column formats** (User's Guide 5-26 to 5-37; Help "Standard Column Properties/Add Box"; screenshot 127). Column Properties ▸ Format, for a standard column, in it and its linked columns:

- **R29 ✅ Numeric columns** (User's Guide chapter 8). A numeric category holds a number for each item assigned to it; the number is a value of the assignment, not a category. A standard category becomes numeric with Category Properties ▸ Type or Column Add ▸ Category type (R55; a numeric category cannot change back, and its Category Properties box shows a date category's shorter set of settings, R6a); its children, if any, are removed and their items get the child's name as their number ("112" → 112, other names → 0), items assigned to the category itself get 0, and Agenda asks first when items or children are affected. A category with grandchildren cannot be converted. Typing in a numeric column enters a number (signs, parentheses for negatives, a currency or % symbol, thousands separators and "3.22e+12" are accepted; anything else is refused); F2 edits it in full, DEL removes it, and the control panel shows "#" at the right of its second line while the highlight is in a numeric column, as Agenda's (beside ♪'s place; a date column shows ☼ there, R59). Numbers are right-aligned and shown in the column's format (View ▸ Column ▸ Properties): label or currency symbol (None, $, %, ¢, £, ¥), decimal places (2; numbers are rounded for display only), thousands separator, negative style (-1 or (1)), Display % of total (a "% tot" column beside the numbers, 5 wide, with each number's share of its section's total, rounded, as "12%"; nothing typed there, and printing to a file adds it after the number; User's Guide 8-7), and the calculations shown at the bottom of every section: count, total (the default), average, minimum, maximum (per column, or for all the numeric columns of a section at once with Section Properties ▸ Select numeric functions, R61). A number too wide for its column is shown in scientific notation. Items sort by their number (R36), Item Properties shows and edits it, the assignment profile asks for it, and printing to a file includes the calculations. Our choices: numbers are binary floating point, as in Agenda; the decimal and thousands characters are the person's (R54), "." and "," by default; calculation lines are not shown under collapsed sections. Section-wide calculation settings are in Section Properties ▸ Select numeric functions (R61); numeric ranges in filters and conditions are R28a and R15a.
- **R29b ✅ Unindexed categories** (User's Guide 3-10 to 3-11, 3-23 to 3-26; checked in Agenda 2.0, 2026-10-25). An unindexed category gives each item assigned to it one text value (a phone number, an address, a part number); the text is a value of the assignment, not a category: it is not matched against item text, nothing is assigned from it, and it is in no hierarchy. A standard category becomes unindexed with Category Properties ▸ Type or Column Add ▸ Category type (Agenda's types in that order: Standard, Numeric, Date, Unindexed), and cannot change back; its children are removed, an item in a child getting the child's name as its text, an item in the category itself an empty one (as a numeric conversion gives numbers; what Agenda does with the children is unchecked). A category with grandchildren cannot be converted. Typing in an unindexed column sets the item's text, an empty one taking it out; DEL removes it. Items sort by their text, case aside. Saved in the file (format 40) and its JSON. In the TUI, as Agenda's (checked in Agenda 2.0, 2026-10-25): the text is typed on the control panel's second line under "Text value:" (no completion), F2 edits the text it has, F3 does nothing (a text has no choices), and ⌂ shows at the right of the View line while the highlight is in the column (Agenda's screen, CP437 0x7F; its help writes D); a filled entry has · before it. Column Add's Category type goes Standard, Numeric, Date, Unindexed, and an unindexed column has no Format; Category Properties ▸ Type lists Unindexed first, then Numeric and Date, and asks Agenda's "Convert to unindexed category (can't be changed back)?". Item Properties lists the text after the name ("Address (12 Grant Ave)"), F4 changing it, as the help's box says (Agenda's screen did not list it there: unchecked); in the assignment profile SPACE on it asks for the text (User's Guide 4-16). The category manager marks it ⌂ (unchecked in Agenda).

### Filters, sorting and search

- **R28 ✅ Filters** (User's Guide chapter 11). A view, and each of its sections, can be filtered by categories: items assigned (or not assigned) to them. All criteria must hold, except that categories that are mutually exclusive are alternatives (same rule as R15). The view's filter shows in brackets beside its name, a section's after its head. Typing an item into a filtered view or section assigns it to the categories the filter requires (of exclusive alternatives, the first), so it stays in sight. Set with View Properties ▸ Filter and Section Properties ▸ Filter (R78, R61; SPACE cycles + assigned · - not assigned · none, as Agenda's "once to show items assigned to the filter, twice to show items not assigned"; ENTER or ESC closes the list, keeping it, R81b).
- **R28a ✅ Date and numeric filters** (User's Guide 11-5 to 11-12). Choosing a date or numeric category in the filter box opens the Date Filter or Numeric Filter box: Show items (Assigned, the default, or Not assigned: items without a date or number), Start and End date (or Minimum and Maximum value; blank leaves that end open, both blank means any date or number) and Items should be (Inside or Outside range). Relative dates ("monday", "today") are kept as typed and read again every day, so "monday" to "friday" is always this week. The filter shows in brackets ("[When 2026-11-05..2026-11-09]", "not" for outside). An item typed into the view or section gets the start date or minimum (with only an end: the end; outside the range: the day or number just before the start, or just after the end). ENTER applies, DEL removes the filter, ESC cancels. Browsing a date filter to other dates (View ▸ Browse, ALT-B) is R48.
- **R36 ✅ Sorting items** (User's Guide chapter 15). A view has sort settings for all its sections; a section can override them or use the view's. Up to two keys (primary, then a secondary for ties): item text; a category — its children in hierarchy order or alphabetically, the date for a date category, the number for a numeric one; or a category note — a chosen line (Line number, default 1) of the note on the child the item is in, compared as text ignoring case (User's Guide 15-18: a town on line 2 of each person's note). Each key has an order (ascending, descending) and puts items without a value at the bottom or top. Ties keep entry order. Set in the Sort box (View Properties or Section Properties ▸ Item sorting), laid out as Agenda's Item Sorting in All Sections / in Current Section (checked in Agenda 2.0, 2026-10-25): Sort new items (shown: When item is entered), then a Primary and a Secondary sort key, each with only the settings that apply: Order and Sort n/a's for Item text; also Category, and Sequence for a standard category, for Category; also Line number (beside Sort on) and Sequence for Category note. SPACE on Sort on goes None → Item text → Category → Category note → None, keeping the category it had (with none yet, the category box opens; Agenda left Category blank until one was picked); SPACE or F3 on Category picks another. A section's box says "(View default)" beside the headings while the section uses the view's settings; any change makes them its own, and ALT-F8 goes back. Our choice: sorting is applied whenever the view is shown, like Agenda's "When item is entered" setting, so "On leaving a section" and ALT-S re-sorting are not needed. ALT-F5 in the category manager sorts the highlighted category's children alphabetically (after Y/N); in the view manager it sorts the views. View Properties sorts the section heads (User's Guide 15-20): Section sorting None (the order they were added in), Category order (as in the hierarchy), Alphabetic or Numeric (names that are not numbers last), and Section order ascending or descending; the sections are shown sorted, and GO TO lists them as shown. Not done: Agenda's Numeric and Date sequences for a category's children.
- **R37 ✅ Search** (User's Guide 15-1 to 15-5). ALT-F6 opens the Search box, drawn as Agenda's with its help lines (checked in Agenda 2.0, 2026-10-26): Search for, Match on (item text, note text, both), Direction (forward, backward, from the beginning) and Ignore case (yes by default); Utilities ▸ Show ▸ Match's box is titled Show Match and has no Direction. Search for is typed as any field in Agenda's boxes: a character starts typing over the text, F2 edits it, and ENTER takes it and stays in the box; a second ENTER searches (checked in Agenda 2.0, 2026-10-26; the owner's choice). A forward search starts after the highlighted item, a backward one before it, so the item highlighted is not itself a match. Search mode is quiet, as Agenda's: no message, the File line shows the date with the time's place blank, and the key bar names F1 Help alone; ALT-N / ALT-P (and F8) go to the next / previous match, and past the last one ALT-N only beeps; F7 marks the highlighted item; ENTER or ESC ends. A search that finds nothing opens Agenda's Error box, "… couldn't find any matches for the text you entered." (any key closes it). Utilities ▸ Show ▸ Match (Agenda's) lists every matching item in the file in the Show view, named **\*Show View\*** as Agenda's and created the first time; ALT-F8 (LAST VW) returns to the previous view. A file has one Show view, as in Agenda (checked in Agenda 2.0, 2026-10-25): Show Match, Sched, Alarm, Prereqs and Depends (and the extras' links) ask "Delete the existing Show view?" when there is one, and ESC leaves it as it is; the control panel says Agenda's "You can have only one Show view. Press ENTER to create the new Show view and delete the existing one." A Show view saved by an older Agendum as "Show View" is the same view, and takes the new name when it is next filled. Utilities ▸ Show ▸ **ItemsDone** shows every done item in it, under a section called **\*Show\***, and **Every** shows every item, under MAIN (User's Guide 13-9, 13-21; checked in Agenda 2.0, 2026-10-25). **Circular** shows the items caught in a circular reference, under a section called **!Circular Reference!** (User's Guide 20-21 to 20-22; checked in Agenda 2.0, 2026-10-26): conditions that keep assigning an item to a category and taking it out again, as "Ed: not in People" with Ed under People; an item is caught when one more round of its conditions would still change it (R15 stops them after a bounded number of rounds). While an item is caught, **o** stands at the right of the control panel's second line, as Agenda's (Help, View Indicators; its column unchecked: column 75, before @). It is worked out when a file is opened and after a key that changed it, for the items that key changed (every item when categories or their conditions changed), not on every key (the owner's choice, 2026-10-26; a key on a file of 2,000 items with conditions takes about 20 ms). Text rules: every word must appear as a whole word, "Pat*" matches any ending, "(a phrase)" must appear as written. Not done: Agenda's other text-condition symbols (? ; , ~ !), and items in collapsed sections are skipped. Searching inside a note is R39.

### Notes

- **R39 ✅ Search and replace in a note** (User's Guide 15-6 to 15-8). ALT-F6 in a note opens the Search/Replace box: Search for, Replace text (No by default; Yes adds Replace with, Global replacement (No) and Confirm replacement (Yes)), Direction (Forward or Backward) and Ignore case (Yes). The text is matched as written, anywhere in a line. A search moves the cursor to the next occurrence and highlights it; ALT-S finds the next one and beeps when there are no more. A replacement replaces the next occurrence, or every occurrence when global; when confirming, each occurrence is highlighted and a Yes/No box asks "Replace this occurrence?" (as the other questions; asked even with Confirm mode off, R54): Yes replaces it, No skips it, ESC stops. The box moves below the occurrence when it would cover it. Our choices: the search starts at the cursor and, when nothing is found after it, continues from the top (backward: the bottom), since a note opens with the cursor at its end; a global replacement covers the whole note; the box remembers its last settings; no length limit (Agenda allowed 25 characters); text never matches across lines. Each replacement is an undo step of its own (the note is saved as it is made; a global replacement without confirming is one step), and typing in the note before the first one is a step before it; the occurrence asked about stays highlighted behind the question box. After a single (not global) replacement, ALT-S replaces the next occurrence (confirming first if asked to), as the Help's "Search & Replace in Note/Macro Box" describes.
- **R63 ✅ Marking, copying, cutting and pasting in a note** (User's Guide 14-4 to 14-8). F7 MARK anchors a region at the cursor; moving the cursor stretches it, either way and over lines, and it shows marked; F7 again drops it, and typing drops it first. F3 COPY keeps the marked text, F4 CUT keeps it and takes it out, ALT-F4 DELETE takes it out without keeping it; with nothing marked each asks, in Agenda's What to copy box (checked in Agenda 2.0, 2026-10-25; the owner's choice; `Agendum.TUI.Boxes.WhatToCopyBox`): one untitled field, "What to copy: Word" ("What to cut:", "What to delete:"), SPACE or a first letter going Word (at the cursor, or just before it), Line, All text, F3 listing them, ENTER taking it, ESC going back with nothing taken; the top line says "Choose how much text to copy. Press ESC to cancel." F2 PASTE puts the text kept at the cursor and keeps it, so it can be pasted again; one piece is kept, for the session, across notes. In a note F4 is CUT, as in Agenda (it used to close the note: ESC and F5 do). Not done: the same keys in item text and category names, and the system clipboard.
- **R64 ✅ Word wrap in the note editor** (ours). A line wider than the screen is shown on as many rows as it needs, so the whole line always shows: a row ends after the rightmost space that fits, and a word wider than the screen is broken at its edge. It is for the screen only: no line break goes into the text. ↑ ↓ move through the rows on the screen, keeping the column in the row: on a shorter row the cursor is at its end, and the next ↑ or ↓ goes on from the column kept (any other key forgets it); HOME and END (CTRL-A, CTRL-E) go to the start and end of the row, and pressed there, to the start and end of the whole line. The note scrolls by rows.
- **R64a ✅ The note editor's control panel and key bar** (Agenda's; NOTE_EDITOR.md step 1; the owner, 2026-10-17). In a note, line 1 of the control panel is `Note for:   ` and what the note is of (an item's text, a category's name), cut with "…" when it does not fit; in the macro editor `Edit macro:  ` and the macro's name. On its right, instead of the mode and the time: the marks (♦ @ ?), then `Line` and the line of the text the cursor is on (a line, not a wrapped row; `Line    1`, `Line  146`), `INS`, and `EDIT`. A message or a question shows over line 1 until the next key, then the header comes back; a hint (the Zettel link under the cursor, R73b) goes on line 2, which is otherwise empty (Agenda showed its font there). A box over the note has the two lines to itself, as anywhere. The key bar is Agenda's, in its slots (R80): F1 Help, F2 Paste, F3 Copy, F4 Cut, F5 Return, F7 Mark, F10 Menu; Agenda's F6 Marker (fonts) is out of scope. ESC asks first when the note changed (R64d).
- **R64b ✅ The note editor's menu** (Agenda's; NOTE_EDITOR.md step 2). F10 in a note (and in the macro editor) opens the note's own menu, not the view's, with Agenda's help lines: **Clear** ("Delete all text in the current note") asks "Clear all text from the note?" (Yes first; at once with Confirm mode off, R54) and empties the note, which stays open; one undo after the note is closed brings the text back, and what was typed before Clear is a step of its own, so it stays. ESC on the question goes back to the menu. **Return** saves and goes back, as F5; **Quit** saves the note and quits, as ALT-Q. **Import** and **Export** are R64c. Agenda's File (external note files) comes with a later step; Print is out of scope. The key bar names F10 Menu.
- **R64c ✅ Importing and exporting a note's text** (Agenda's; NOTE_EDITOR.md step 3). The note's menu (R64b): **Import** asks "Text file to import into the note:" (F3 lists the folder's `.txt` and `.md` files, R51) and puts the file's text in at the cursor, which ends after it; CR LF and CR are read as LF (Agenda asked whether to strip carriage returns; Agendum always does). The message line says "Imported <path>"; a missing file says "File not found", and a file that is not text (not UTF-8) "Not a text file: <path>", the note unchanged. **Export** asks "Export the note to text file:" (F3 lists the same) and writes the note's text there, LF line ends and a final newline, replacing a file that is there ("Wrote <path>"). What Import put in is like typing: it is saved with the note when it closes. The shell reads and writes the files (`{:read_note_text, path}`, `{:write_text, path, text}`).
- **R64d ✅ ESC in a note: Discard changes?** (Agenda's; NOTE_EDITOR.md step 4; the owner's choice, 2026-10-17). F5 saves the note and goes back, without asking. ESC goes back at once when the text is as it was when the note was opened; when it changed, a box asks "Discard changes?" with **No** shown first (SPACE switches, Y and N answer): No (ENTER) saves the note and goes back, as F5; Yes puts the note's text back as it was opened and goes back, what Search/Replace (R39) and Clear (R64b) saved on the way included, so the file is as before the note was opened (Yes after such a saved step is itself one undo step); ESC on the question goes back to the note, as it was. The question is asked whatever Confirm mode says (R54): its answers do different things. The same in the macro editor. ALT-N / ALT-P (to the next or previous note), Return and Quit keep saving without asking (the owner's choice, 2026-10-17; Agenda "optionally" saved there).
- **R64e ✅ The note editor's editing keys** (Agenda's; NOTE_EDITOR.md step 5; the owner, 2026-10-17). In a note and the macro editor: CTRL-← / CTRL-→ (⌥← / ⌥→) move a word left or right, a word as one-line fields have it (spaces skipped, then the word); from the start of a line the move goes on to the start of the last word above, from the end to the end of the first word below. CTRL-BACKSPACE where the terminal sends it, ⌥⌫ or CTRL-W delete the word before the cursor (at a line's start they join it to the line above, as BACKSPACE); ALT-W deletes the word after it (at a line's end, the line break). CTRL-K deletes from the cursor to the end of the line (Agenda's CTRL-ENTER, which terminals send as ENTER; the owner's choice); at the end it does nothing. ALT-M breaks the line, as ENTER. PGUP / PGDN move as many rows as the screen shows, as ↑ ↓ do (through wrapped rows, R64). CTRL-HOME / CTRL-END (⌥< / ⌥>, as Emacs, for keyboards without them) go to the start and the end of the note. A key that changes the text drops the mark (R63); a move keeps it, stretching the region. **INS** (or CTRL-N, which stands for INS everywhere) switches between inserting and typing over, shown as `INS` or `OVR` in the header (R64a); typed over, what is typed replaces as many characters after the cursor, as far as the line goes (pasting and TAB insert). It is the note's own: a note opens inserting. **TAB** types spaces to the next tab stop, **File Properties ▸ Tab size** apart (Agenda's, stored in the file: 5 in a new file, 1 to 16; typed as a number in the box, as Agenda, or SPACE for the next, F3 for the list; one undo step). Agenda kept tab characters and showed them at the tab stops; Agendum types spaces (the owner's choice, 2026-10-17), so a note reads the same anywhere.
- **R64f ✅ A note's connections: APPEND, GETITMS, the calendar** (Agenda's; NOTE_EDITOR.md step 6; User's Guide 12-7, 12-10). **ALT-F9 APPEND** moves text from the note to the end of the item's text (in a category's note, of the category's name), after a space: the marked text, or else what a box asks for, Word (first), Line or All text, as F3 COPY does (R63); line breaks become spaces. What does not fit (350 characters for an item, 69 for a category name) stays in the note, at the cursor; with no room at all, nothing moves. The shorter note and the longer text are one change (one undo step); the item's text is edited as typing it would (its dates and text matching again); the header shows the new text. In the macro editor it says it appends only to an item or a category. **ALT-F8 GETITMS** asks Agenda's "Discard items after copy?  Yes" (checked in Agenda 2.0, 2026-10-26, as User's Guide 12-7 says; an earlier try had lost the key), asked whatever Confirm mode says as its answers do different things; either answer types the marked items in at the cursor, each item's text with its note under it, the items separated by blank lines, a blank line before and after; Yes then discards them, to the trash (R24a), No leaves them marked; ESC copies nothing ("There are no marked items in the file." when none). **ALT-C** opens the calendar (R46) on today: ENTER types the highlighted date at the cursor in the file's date format (R41), with the time F6 gave; ESC types nothing.

### Clock and alarms

- **R38 ✅ Clock and alarms** (User's Guide 10-16 to 10-20). The title bar shows the date and time, as Agenda's (checked in Agenda 2.0, 2026-10-25): the date, two spaces and the time right-aligned in seven columns, at the end of the line (`10/25/26   9:18pm`, `10/25/26  10:30am`; `2026-10-25    09:05` on a 24-hour clock). The item shows "@"; ALT-A on it cancels the alarm at once, without the box. A date category that is deleted leaves its alarms on When. When the time comes the alarm rings: Agenda's alarm tune (R76), a message naming the item, and "@" in column 76 of the control panel's second line while the past alarms list an item, as Agenda's (checked in Agenda 2.0, 2026-10-25: opening the list leaves it; it goes when the last past alarm is removed or forgotten). Utilities ▸ Show ▸ Alarm shows the alarm list as Agenda's (checked in Agenda 2.0, 2026-10-25): the Show View with two sections, **!Current Alarms!** (the items with an alarm set, in the order they ring, those without a date last; each shows "@") and **!Past Alarms!** (the alarms that have rung, the latest first). It is a view like any other; DEL on an item asks Agenda's "Remove this item from the section?" and then cancels a current alarm or takes a past one off the list, the item staying; the question has Agenda's second line, "(Use ALT-F4 to discard the item completely.)", and its help on the control panel. The two sections are stored as two MAIN sections, so each can have columns; the view model fills them. Past alarms are forgotten when the date changes, and when the file is opened on a later day. Our choices: ringing is not an undo step, nor an edit (R70).
- **R70 ✅ While you were away** (ours; meeting 2026-10-16, § 6). When a file is opened (at startup, Retrieve, or Import) and alarms came due while it was closed, they ring quietly (no bell) and a "While you were away" box lists them, after the splash screen, which is unchanged: "3 alarms came due:", then one line a group, the latest first, with when it was due and the text; alarms with the same text are one line with a count ("×2"); past the room there is, a last line says how many more and that Utilities ▸ Show ▸ Alarm lists them all. ENTER or ESC closes it; the alarms then sit in Utilities ▸ Show ▸ Alarm with the other past alarms. No box when nothing came due. A rung alarm records the time it was due, not the time it rang. Ringing is not an edit: the clock's changes (alarms rung, old ones forgotten, conditions rechecked on a new day) are made to the file as last saved as well, so they never cause a "Save changes?" question by themselves; quitting without saving rings the same alarms again next time. The grouping is the core's (`Agendum.Core.group_alarms/2`), for a web page too. ### Colours and dates on the screen

- **R40 ✅ Colour themes** (Setting Up Agenda 1-25 to 1-31). The screen is drawn with a theme chosen at start: `classic` (the default: Agenda 2.0's colours, from screenshots of the real program, ADR 0018), `mono` (bold, dim, underline and reverse only), or one of six terminal colour schemes (`docs/THEMES.md`): `modus_operandi`, `modus_vivendi`, `alabaster`, `zenburn`, `ayu` and `borland`. The theme is a personal preference, not part of the file, as in Agenda, where Utilities Customize set Color (Mono, Color, Plasma or Custom, with a colour for each screen element) for all files. Custom colours are not planned: a new look is a new theme (ADR 0022).
  - `classic`: black text on a grey screen; section heads, column heads and column entries in blue; the highlight white on red; title bar and control panel white (hints yellow) on blue; boxes cyan in a solid blue frame, the title centred in the frame, with a black shadow below and to the right, and the screen behind them greyed out; the category manager on cyan; help yellow on blue. The VGA colours are exact on terminals that take 24-bit colour (`COLORTERM=truecolor`), the nearest ANSI colours elsewhere.
  - A box opened from another box sits one line lower and two columns further right, so the one beneath still shows, and the titles of the boxes beneath are dimmed (our choice).
  - `mono` has the same parts in bold, dim and reverse video: the control panel in reverse video, the highlighted line in bold, box titles and dimmed titles, the faded screen behind a box.
  - The terminal schemes share one layout in their own colours (`Agendum.TUI.Terminal.Theme.Palettes`): the screen in the scheme's background and foreground; the control panel, menus and the line being edited in its selection colours; the highlight in its cursor colours; the highlighted line, boxes and the key bar on a tint of the background; heads, entries and box frames in its blue; the help box on a background of its own, apart from the screen and from its pane. Exact on 24-bit terminals; elsewhere they use the terminal's default colours and its ANSI colours, so a terminal set to the same scheme still shows it. Typed as `modus-operandi` or `Modus Operandi` too.
  - Our choices: the highlighted line is drawn in a lighter shade across the whole screen, so it shows when the highlight is in a column; Agenda put a » in front of it instead.
- **R41 ✅ Date display format** (User's Guide 6-20 to 6-22, 7-13 to 7-15). File ▸ Properties ▸ Global date settings ▸ Display format sets how the file displays dates and times, as Agenda's global Display Format (drawn as Agenda's, like a date column's Date Column Properties, R41a: only the settings for what the dates display): Date format (Agenda's 14 orders, from MMDDYY to DDMMMYYYY), Date separator (- . , space : /), Clock (24 or 12 hr; 12 shows am/pm) and Show day of week, with a formatted sample. It is stored in the file and used everywhere a date is shown: date columns, the title bar clock, Item Properties, the alarm list, messages and printing. A new file starts with Agenda's default (checked in Agenda 2.0, 2026-10-25): Date time, MMDDYY with "/", a 12-hour clock with am/pm, ":" ("10/25/26 9:10pm"); F8 Default in the box gives it back, and a file keeps the format it has. A file imported from Agenda (R72) keeps its own global format (header word `0x182`, decoded 2026-10-26). ISO 8601 is one of Agenda's choices (YYYYMMDD with "-" and 24 hr); files from before format 7, which had no format, show it. Our choices: dates with a month name always use spaces; dates offered for editing stay ISO 8601. More options and date columns of their own: R41a. The Input format settings: R41b.
- **R41b ✅ Input format** (User's Guide 7-14, 7-17). How a person types dates and times: Number order (MDY, MYD, DMY, DYM, YDM, YMD; "12/11/90" in DMY is 12 November 1990, and a month and day alone keep the order's sequence, "12/11" in DMY), Input date separator (/ - . , :; it replaces the slash, also after a month name: "nov.12") and Input clock (12 hr: "3:00" is 3 pm, between Morning and 12 hours later; 24 hr: as written). Each is "Language (…)" until set: the date language's numeric order, "/" and clock. Our choice (ADR 0008, 0013): these belong to the person, not the file, unlike Agenda; Global date settings ▸ Input format opens the box ("yours, for every file"), and a change applies at once, is not undone with the file, and is saved in the person's preferences file (`~/.config/agendum/preferences`, or under `$XDG_CONFIG_HOME`), plain `key = value` lines, which Utilities ▸ Customize also writes (theme, date languages; it opens this box too). Only the setting changed is saved, never one a flag gave for the session. `--number-order`, `--date-separator` and `--clock` set them for one session. ISO dates (2026-10-20) are always read; with ":" as separator, "3:30" is a date, as in Agenda.
- **R41a ✅ More date display options** (User's Guide 6-19 to 6-22, 7-14 to 7-15). The Display format box has all of Agenda's Display Format box, in its order: Display date and/or time (Date time, Date only, Time date, Time only; a date column with only a date shows the date, and with Time only nothing), Show day of week, Date format, Date separator, Clock, Show am/pm (Yes: "3:25pm", No: "3:25") and Time separator (":" or hm: "3h30m"). Date format adds Agenda's counts: <Day> # ("317"), Day # ("Day 317"), <Week> # ("46"), Week # ("Week 46"), Relative and Relative # ("1 day", "-2 days"). Relative shows Today, Tomorrow, Yesterday, and "nxt Sun" or "lst Fri" within six days, as Agenda 2.0 does (Lotus Q&A "Relative Date Format is Displayed for only Seven Days"); other dates are shown in the global format. Our choices: weeks are ISO 8601 weeks (the manual's sample says Week 45 for 13 Nov 1990, a US count; ISO says 46); the title bar clock and alarms always show date and time, and relative formats are used only in date columns (elsewhere, ISO 8601 or the global format). View ▸ Column ▸ Properties on a date column opens the Date Column Properties box: A line under the part's title says "(Global defaults)" until a setting is changed, then "(Local settings)", and the column keeps its own format while the file's changes; ALT-F8 goes back to the global defaults. ## 5. User interface (Agenda 2.0 conventions)

### The screen and the control panel

Screen: Agenda's two-line control panel, the body, and a function-key bar. The control panel shows the file with the indicators (marks; Agenda's mode words only, LEARN, AUTOC, EDIT, BROWSE, WRKG while a calendar or feed is read in the background, and none when ready, in boxes, menus and managers, as Agenda's, checked 2026-10-25) and the time on its first line (the category manager shows neither, as Agenda's), and what is shown on its second: the view with its filter and hide settings, or "Category Manager", "Note for: …", "Help". The hide settings follow the view's name and filter in one bracket, as Agenda's (checked in Agenda 2.0, 2026-10-25): "Hide" written once and the settings in Agenda's order, `View: Projects [Hide empty, done, inherited, dependent]`, straight after a filter (`View: People [-Contact List][Hide done]`); in a datebook view the bracket loses its space and is cut short with ".." before "Datebook For:" (`View: Tomorrow[Hide empty, done, in..] Datebook For: When`). Our choice: "[No Auto Dates]", Agendum's warning that new items get no dates (R6b; Agenda has none), stays at the right. While an item's text is typed (a new item, or F2 on one), the two lines stay the File and View lines, as Agenda's (checked in Agenda 2.0, 2026-10-25; the owner's choice): no hint, and at the top right the date, then EDIT where the time was (`2026-10-25 EDIT`). The menu (its entries, then the highlighted entry's commands or description), a prompt (its label, then the field), a message or a hint take it over while they last; messages and hints keep the indicators beside them and go on into the second line when long, as Agenda's help lines did. While a box is open (the view manager, the assignment profile and a question too), the two lines are the box's alone, as Agenda's (checked in Agenda 2.0, 2026-10-25): no file, time, marks or view. Line 1 says what its highlighted field does and which keys change it ("Choose to insert new columns in one or all sections in the view."; screenshots 130 to 143), going on into line 2 when long, line 2 blank otherwise; a list box (Go to, Copy, Calendars…) has one such help for the whole box. While a field is typed in (F2, or typing over it), line 1 is blank but for the mode word at the right (EDIT, or AUTOC with completion), and the help comes back when the typing ends. A message comes first. The texts follow Agenda's (its F1 help's tables of settings), with Agendum's keys (`Agendum.TUI.Boxes.FieldHelp`).

### ESC in the menu

In the menu, ESC backs up one level; a box, prompt or question opened from the menu goes back to the menu level it was chosen from on ESC, and ESC again backs up until the view, as in Agenda (User's Guide 2-13: "back up one step at a time"); finished any other way (ENTER), it goes back to the view.

### The view manager

The view manager is a box over the view, as Agenda's (screenshot 40): the views' names in order, * before a datebook view, ► before the view shown (R68), an arrow where the list goes on; ENTER shows the highlighted view, ESC goes back to the one shown, F4 (or DEL) discards one; F5 lists the views by recently used (R68). Our choice: Agenda's view manager showed no more, so each view's sections are no longer listed beside its name.

### Questions

A Y/N question is a small box without a title, as Agenda's (screenshots 36, 141): the question, then its answer highlighted, Yes at first; SPACE (or an arrow) switches it, ENTER accepts the answer shown, ESC cancels. Our choice: Y and N answer at once (Agenda's first letter only picked the answer).

### Finishing a box: ENTER and ESC

A message for a situation Agenda also met is Agenda's, adapted (`Agendum.TUI.Messages`; the owner's choice, 2026-10-25): "The highlight isn't on an item.  Highlight the item you want and repeat the command.", "The date you entered isn't valid.  Type a valid date."; what Agendum does otherwise is left out of it (ALT-C's calendar, the trash, DOS advice), and one too long for the control panel's two lines is cut to its first sentences. A box's title is Agenda's, in its capitals and without the name of what it is for ("Category Properties", "Section Properties", "Item Sorting in Current Section"); a category's Advanced settings box is "Advanced Settings for" its name, short name and Also match words joined by ";", cut at 20 characters with "..." ("Advanced Settings for Calls;Phone;Telephon..."); labels end in a colon with the values in a column after them, as Agenda's (checked in Agenda 2.0, 2026-10-25; `test/agendum/tui/agenda_boxes_test.exs` compares the boxes with Agenda's). A box's bottom edge says how to finish it, in Agenda's words (screenshots 130, 138, 144): "Press ENTER when done, ESC to cancel" on a settings box, "Press ENTER to accept, ESC to cancel" on a box to choose from, "Press ENTER to accept" on a category list opened from a box (R81b). In every settings box ENTER is done and ESC cancels, as in Agenda: its changes show in the box at once, but the screen behind it stays as it was until ENTER, as Agenda's (checked in Agenda 2.0, 2026-10-22; ADR 0030, amended; the owner's choices, 2026-10-24); after ENTER the whole box is one undo step, and ESC puts the file and your preferences back as they were when the box opened, leaving no undo step (a cancelled box changed nothing); an auto-save waits until the box has closed; a box opened from a box cancels only its own changes, and work done in a full screen opened from a box (a note, the macro edit screen) stays. ESC while typing in a field only stops the typing (`Agendum.TUI.Boxes.BoxCancel`).

### Moving and changing settings in a box

In a box the arrows move between settings as in Agenda (User's Guide 2-16, `Agendum.TUI.Boxes.BoxNav`): → or TAB right one setting, or on to the next when there is none to the right; ← or SHIFT-TAB left, or back to the previous; ↓ ↑ to the next or previous row, onto the setting nearest the same place (from a right-hand setting to the right-hand one below, or the left one when the row has only that); HOME / END the first / last. On a text or date being typed (Search, a range filter, an action's value), ← → HOME END move in the text instead. A setting is changed with SPACE (the next choice), edited with F2, picked from with F3; a number (a width, decimal places, a line number) is typed, and so are Morning, Afternoon and Evening (SPACE asks). On a setting with a list of choices, as in Agenda, a letter picks the next choice starting with it ("r": Relative; one undo step), and F3 (CHOICES) lists them in a box, the current one first, titled "Choices" with nothing in its bottom edge, as Agenda's (checked 2026-10-25). The choices are what SPACE goes through (`Agendum.TUI.Boxes.BoxChoices`); on a setting that is typed, letters are typed as before.

### Category and File Statistics

In Category Properties, as Agenda (screenshot 74), Note, Statistics and Advanced settings show "..." and SPACE opens each one's box; the Category, File and View Statistics boxes say "Press any key to continue" in their bottom edge, and any key closes them, as Agenda's (checked in Agenda 2.0, 2026-10-25); Statistics (Agenda's Category Statistics) counts the items in the category, its children, the sections it heads, and the view filters, conditions and actions that name it. - **R82 ✅ Agenda's File commands** (User's Guide 22-8 to 22-12, 23-26; checked in Agenda 2.0, 2026-10-25). **File ▸ Abandon** opens Agenda's Abandon File box, "Revert to last saved version: No" (No first; SPACE, Y or N change it): ENTER on Yes puts the file back as it was last saved, or as it was opened when it has not been saved since; ENTER on No and ESC leave it. Our choice: going back is one change like any other, so undo brings the abandoned changes back. **File ▸ Maintenance ▸ MakeCopy** (in place of our former File ▸ Write, a change back settled with the owner) asks for a name (F3 picks one) and writes a copy of the file there, whatever is at that name, as Agenda's caution says; the file is saved too, and you go on in it (Retrieve the copy to work in it). Our choice: the copy is written first and the file saved after (Agenda saved first), so that when the file changed on disk and is not saved over (R71), the changes are kept in the copy; an untitled file only writes the copy. **File ▸ Maintenance ▸ Erase** asks for a file (F3 picks one) and Agenda's "Discard owl.agendum?  No" (No first; the control panel: "Press Y to discard the file from your disk."); the open file is refused with Agenda's "You can't discard a file while it is open." Our choice (the owner's): Yes moves the file to the system's Trash, where it can be got back, rather than deleting it (a Mac's `~/.Trash`, Linux's XDG Trash with its `.trashinfo`; elsewhere the file is kept and the message says so); a backup beside it stays, as in Agenda. **File ▸ Transfer ▸ Template** asks for a file name (F3 picks one) and writes the file's structure there, whatever is at that name: its categories, views, macros, conditions and actions and settings, without its items and so without any assignment, value, dependency or suggestion (a Show View listing items lists none). **File Properties** has Agenda's **File description** (typed, up to 40 characters; "Enter a short description of the file.") and **Make backup on open** (No; "Choose whether to back up the file automatically each time you open it."), both kept in the file (format 42): with Yes, opening the file first copies it to `NAME.agendum.bak` beside it, replacing the last backup (Agenda's `.BG`); the backup is not listed among the files to open, and renamed to `.agendum` it opens as any file. F8 in the Select File box (R51) shows each listed file's description beside its name, read from the files, as Agenda's F8 DESCRP; F8 again hides them. **Set file password** (ADR 0046; checked in Agenda 2.0, 2026-10-26) opens Agenda's small boxes in turn, the password typed hidden: "Enter the current password" when the file has one ("The password you typed is incorrect." when wrong), "Enter the new password", "Please type the new password again" (when the two differ, Agenda's "The second password you typed didn't match the first one. Retype the second password entry or press ESC to start over."); an empty new password removes it; up to 12 characters. A file with a password is saved encrypted and opening it asks for it ("Password of owl.agendum:"; a wrong one: "The password you typed is incorrect. Retype …"), at startup too. File ▸ Retrieve with a name that is not a file yet opens Agenda's **New File** box, Description and Password, both optional (our former question "Create the new file …?" gives way to it); ENTER makes the file, not saved yet, ESC keeps the one open. A forgotten password cannot be recovered. The JSON export is plain text, and says so for a file with a password.
- **R82a ✅ Update defaults** (User's Guide 22-14, 17-50, H-9; checked in Agenda 2.0, 2026-10-26; meeting 2026-10-26-3, §§ 5–6). File Properties' last row, **Update defaults ...** ("Use these File Properties as defaults when creating a new file."), opens Agenda's untitled question "Update new file properties? Yes" ("Press ENTER to accept, ESC to cancel"; SPACE, Y or N change it). ENTER on Yes keeps the file's settings as the person's defaults for new files at once: File Properties (Make backup on open, Insert new columns in, Empty trash, Tab size), the global date settings with the display format, and the auto-assign settings; not the description or the password, as in Agenda. File Properties then keeps its changes even if ESC follows, as Agenda's did (one undo step). ENTER on No and ESC keep nothing. Every empty file the person makes from then on starts with them: File ▸ Retrieve with a name that is not a file yet, and `agendum` with a new name or none; files they already have keep theirs, and starters, samples, the demo, imports and copies keep their own. F8 Default in File Properties and its boxes gives the person's defaults, as Agenda's did. A new file without them has Agenda's settings (MM/DD/YY): Update defaults is the only way to change that. Agenda kept the defaults in its program's settings file (`AGENDA.ENV`); Agendum keeps them in the person's preferences (ADR 0008), as `default.` lines for the settings that differ from Agenda's (our choice), so a setting never changed follows Agendum's own; a line it cannot read is ignored. Printing is out of scope (SPEC § 6), so the print settings Agenda saved with them are not.
- **R82b ✅ A recovery file on a crash** (meeting 2026-10-26-4, § 6; the owner's choices, 2026-10-26; Agenda's Damaged File box, User's Guide 22-15). When Agendum crashes with unsaved changes, it writes them beside the file before stopping, under Agenda's name for a damaged file's changes: `notes.agendum` → `notes@.agendum` (Agenda: `MYINFO.AG` → `MYINFO@.AG`); an untitled file's go to the state folder (`~/.local/state/agendum/untitled@.agendum`). The terminal, once back, says where ("Your unsaved changes were kept in …"). The next time the file is opened, Agendum asks "notes.agendum: changes not saved before a crash (date and time) are in notes@.agendum. Open them? Yes": Yes opens them as unsaved changes to the file, and the save that keeps them removes `notes@.agendum`; No opens the file as last saved and moves `notes@.agendum` to the system's Trash, as Erase does (R82); ESC decides nothing, and the question comes again next time. A file with a password keeps its changes encrypted with it. Our choice, as Agendum cannot show a box once it has crashed: Agenda offered to save the changes to the @ file, which then had to be repaired with its DB2STF utility. Only a crash Agendum catches writes them: not a power loss or a killed process (Auto-save, R54, saves into the file itself).
- **R82c ✅ Text from outside is data** (meeting 2026-10-26-4, § 6; expert review 2026-10-21, § 14). Text that comes from outside, a feed (R75), a Lotus Agenda file (R72) or a JSON file (R44), is kept as plain text: nothing in it runs, whatever it says ("discard every item"), and Agenda's macro commands in it (`{MENU}`) are only characters; it becomes items of its own and changes nothing else in the file. Control characters in any text are shown as characters, never sent to the terminal, so escape codes cannot clear the screen, set the window's title or write the clipboard: bytes 0x00 to 0x1F as the glyphs DOS showed for them, as Agenda's screen did (ESC as ←, BEL as •), DEL as ⌂, and the C1 controls (U+0080 to U+009F, which DOS never had) as "?". The text itself is kept as it came, so an export gives it back unchanged.

### Rules of the user interface

- **R42 ✅ The original keys** (Help: "Agenda Key and Menu Charts", in `docs/reference/Agenda 2.0 Help File.html`). Keys follow Agenda's charts; where we added a key of our own it must not take one Agenda used for something else. In views: ALT-F5 GO TO (a list of the view's section heads; ENTER highlights the chosen one), ALT-N / ALT-P next / previous view, ALT-W save, ALT-G retrieve, ALT-Q quit, ALT-V show/hide empty sections, ALT-K show/hide the key map, ALT-I insert an item. In the category manager: ALT-R insert a child, ALT-L insert an "uncle" (a sibling of the parent, after it), ALT-D / ALT-I insert a sibling below, ALT-U above. In notes: ALT-D / ALT-T insert today's date / the time, ALT-N / ALT-P go to the note of the next / previous item (or category). ALT-F5 used to open the Sort box (R36); the Sort box is now reached through the menu. ALT-K and ALT-Q also work in the managers and in notes (ALT-Q saves the note first). In a note, ALT-N / ALT-P save it and move the highlight with them: in a view to the next / previous item (or, for a section's note, section), in the category manager to the next / previous category; elsewhere they do nothing. Not done: a category added to a family whose other members are all sections of a view does not become a section of that view (User's Guide 16-11). ALT-F9 COPY (User's Guide 13-8 to 13-9): the Copy box lists the view's sections, the current one highlighted; ENTER puts the item (or, after asking, the marked items) in the chosen one as well, assigned to its head and keeping its other sections, one undo step. It is the same item, not a duplicate; a mutually exclusive section head takes it away from the old one (R15). Our choices: Agenda put the copy at the bottom of the section, but a file's items have one order, so it shows in its usual place; not in a datebook view, whose sections are dates. ALT-Y yank back (User's Guide 4-10): the item last taken out of a section with DEL goes into the current section, below the highlighted item (on a section head, in its usual place), assigned to the section's head, one undo step; it can go back where it was or anywhere else. One is remembered, and removing marked items does not count, as in Agenda; after a yank there is nothing left to yank. Agenda's help says ALT-Y also recovers the latest discarded item; in Agenda 2.0 it did nothing after a discard (checked, 2026-10-26), so ours does not either: Item ▸ Undisc does (R24a). Not in a datebook view. ALT-H hop (User's Guide 13-9): the highlighted item's next occurrence, in a later section of this view, else in the next view that shows it (the view manager's order, round to the first; the control panel names the view; ALT-F8 goes back); "No other occurrence" when it shows only once. Items in collapsed sections are not found. In a note (User's Guide 12-8 to 12-9): ALT-F7 MAKEITM asks Word, Line or All text and makes that text a new item in the section the highlight is in, below the note's item, taking it out of the note (line breaks become spaces; past 350 characters the rest is the new item's note); the shorter note and the item are one change. Only in a note opened from a view. ALT-F2 MAKECAT makes the word at the cursor (its punctuation off) a new category under a parent picked from the hierarchy; the note keeps it (past 69 characters the rest is the category's note). With text marked (R63), both take the marked text without asking. Later, with their features: ALT-B browse, ALT-C calendar, ALT-O dependency, ALT-E / ALT-X execute conditions and actions, ALT-Z run macro, ALT-S sort now.

Extras that are not in the original (details in `KEYBOARD.md`):

- **R30 ✅ Undo/redo** (CTRL-Z / CTRL-Y, menu Undo/Redo). Every action that changes the database is one undo step. Undo returns to the view and item where the change happened. It is available in views and in the category and view managers, but not while typing. Undoing back to the last save clears the "modified" marker. History holds 100 steps.
- **R31 ✅ Keyboard alternatives.** Function keys are required, as in Agenda: ESC+digit is not an F-key (ADR 0032). ALT-letters are ⌥-letters on a Mac with Option as Meta (the terminal sends ESC and the letter together; ESC then a letter typed by hand is ESC, then the letter). CTRL-N = INS, CTRL-E = F2, CTRL-K = F4, CTRL-D = discard, CTRL-S/O/P/Q = save/open/print/quit. ⌥↑/⌥↓ jump between sections. Text fields use Mac/emacs editing keys. ⌘ shortcuts are mapped onto these CTRL keys by the terminal.
- **R65 ✅ Commands, keymaps and a count** (ours, after Emacs; ADR 0033). Since R65e the help's pages are reached as Agenda's: F1's text is the topic for where you are, and `a`, `c` and `d` below are F6 Keys and its two links, Commands you can run here and Describe a key. ✅ In a view, a note and the category and view managers, every key runs a named command (`Agendum.TUI.Commands`) through that place's keymap (`Agendum.TUI.Keymap`), ALT-letters included; a printable character that is not bound starts typing. ✅ A count: ALT-digits typed in a view (ALT-1 ALT-0) are shown in the control panel and make the next command run that many times, for commands that take a count (moving the highlight, next marked item, hop, next and previous view); a repeat that changes nothing, or that reports an error, stops the count; other commands run once; ESC drops the count; at most 999. ✅ F1 shows a text about where the person is: the view, a note, the category or view manager, the menu, a move, or the box on top (each box's own, else one made from its title, how a settings box works and the highlighted setting's help). From it, `a` lists all the keys, made from the keymaps: those of almost everywhere first, then the view's, the note's and typing's, then the rest, with a few words for Mac keyboards. ✅ In the help screen (F1), `c` lists the commands that can run where F1 was pressed (a view's own, then those of every screen: undo, save, quit …), with their keys and summaries; ↑↓ move, ENTER runs the highlighted one there, ESC returns. Typing narrows the list to the commands whose name matches what was typed, fuzzily, best first, then those whose summary holds it (R65d; BACKSPACE takes a letter back; ESC first forgets it all). `d` then a key says what that key does there: the macro attached to it (and the command it hides), a key of every screen, the view's command and whether it takes a count, or what a key that stands for another (CTRL-N for INS) stands for; the key is not run, and any key then returns. ✅ The category manager's, the view manager's and a note's keys are in keymaps of their own too, so `c` and `d` work there (F1 opens the help in the view manager and in a note too; ⌥↑ ⌥↓ move a category or view there, as in Agenda, while in a view they stand for CTRL-PGUP / CTRL-PGDN). In a note the keys of every screen are not listed: they edit the text there (CTRL-E is the end of the line, not F2). ✅ In a box F1 opens the help too (not while typing in one of its fields): `c` lists the box's own keys as its key bar names them (ENTER presses that key in the box), then the keys every box shares (F1, F3 a setting's choices, ESC cancel) and the keys of every screen; `d` describes a key from the same lists. Every box has a keymap of its own (a settings box: the moves, SPACE change, ENTER done, ESC cancel, and its own keys), so its commands are listed from it; letters a box reads itself (typing a name, a number, finding a line) are described as typing. ✅ In the menu F1 opens the help too: `c` lists the entries of the level shown, each by its first letter (ENTER chooses one), then the menu's keys; `d` says which entry a letter chooses. The keys of every screen are not listed there (they do nothing in the menu). ✅ The same while moving items, a column or a section, changing a column's width, browsing dates and searching the view: each has a keymap, and F1 opens the help there. Typing keys are in keymaps too (one line, and a note's text), so describe key names them in a note.
- **R65a ✅ Commands that cannot run now** (ours; Agenda had no command list). The command list (F1, then F6 Keys ▸ Commands you can run here; R65's `c`) lists every command of the place, but greys those that cannot run now (the Mac's menus grey them too): a command stays where it always is, so its place in the list can be learnt, and what the place offers can still be seen. The highlighted one says why on a line under it ("Not now: No removed item to yank back"); ENTER on it shows that reason instead of running it. Typing to narrow the list highlights the first match that can run, so typing then ENTER runs something. `d` adds the reason to a key's description. A command cannot run when running it would do nothing, or only report an error: Yank with nothing removed, Next marked and Unmark all with nothing marked, Copy, Hop and Alarm on a section head, Done, When and MakeAssign on a section head with nothing marked, Undo with nothing to undo, Rename and Discard on MAIN, Promote at the top level, Move up on the first sibling or view, Paste in a note with nothing copied … A command that asks first (Discard on an item) can run. Each place says which of its commands cannot run (`unavailable/1` beside its `run`), with the same reason the command gives; a test runs every command said not to run and checks that it changed nothing.
- **R65b ✅ The commands' longer texts** (ours). A command can have a longer text than its summary, saying what the summary has no room for, above all why one would use it where that is not obvious (Remove takes an item out of one category only, so other views still show it; Copy files one item in two places). The command list shows it under the highlighted command, wrapped below the keys, and describe key after a key's summary (both reached through F6 Keys, R65e). A command whose summary says it all has none. The view's, the global ones, the managers', a note's, every box's shared ones and each box's own (Change and Done of a settings box are shared by all of them), and the menu's entries, by their labels: an entry that runs a view's or a global command (Item ▸ Alarm is ALT-A) has that command's text, so the two cannot drift apart (`Agendum.TUI.CommandDocs`).
- **R65c ✅ The help screen's frame and pane** (ours; the owner, 2026-10-16). The help is a box over the screen it was opened from, centred, leaving a margin of the faded screen around it: at most a tenth of the screen on each side, less on a smaller screen, where the help needs the room more (80×25: about nine tenths; 200×60: four fifths), framed with "Help" in its top edge and a shadow, while the screen beneath (with any box open on it) fades as behind any box, so opening help changes less of what is seen. Every help page (F1's text, `c`, `d`, `a`) has the same frame: a heading in a colour of its own, with the page's keys on its right; a line under it; a rule. The heading stays while the page scrolls. The command list leaves a pane of five lines at the foot, under a rule: the highlighted command's name and keys, why it cannot run now (in the error colour, on the right), and its longer text, or its summary when it has none, four lines at a time (← → page through a longer one; the rule says "← → 1/2"). The pane never changes size, and the list scrolls only when the highlight would leave it, so the commands do not move as the highlight moves; the rule says how many are above and below. A summary too long for the screen ends in "…". The colours follow the theme (`help_title`, `help_rule`, `help_pane`, `help_pane_title`, `help_frame`): in the classic theme a white heading and frame, cyan rules and a black-on-cyan pane, like Agenda's boxes.
- **R65d ✅ Run a command by name (CTRL-X)** (ours; meeting 2026-10-16-3, § 7; ADR 0040). CTRL-X opens a small box, **Run a command**, shaped like Agenda's choice lists, wherever the command list shows commands (a view, the managers, a note, a box, a move), but not in the menu, nor while typing a line or answering a question: an input line, the commands that can run there and now (those the command list would grey are left out), one a line with its first key on the right, and the highlighted one's summary at the bottom. Typing finds a command by its name, in any case and with spaces ignored: a name that starts with what is typed comes first; then one with a word starting with it, or whose words' initials it is ("azi" is Attach Zettel id); then one holding its letters in order, the closer together the better; then one whose summary holds it. Among equals the commands last run by name (from CTRL-X or the command list, this session, the last ten) come first, then the command list's order; with nothing typed, the last run by name first, then the whole list. ↑ ↓ HOME END choose, BACKSPACE takes a letter back, ENTER runs the highlighted command where CTRL-X was pressed, as its key would (one undo step, as the key's), ESC closes and changes nothing. The command list's narrowing uses the same matching (`Agendum.TUI.Commands.match/3`, which the web's palette is to reuse); with nothing typed it keeps its fixed order. A command without a key of its own can be run this way too.
- **R65e ✅ Agenda's help** (Help: "How to Use Help"; checked in Agenda 2.0, 2026-10-26; meeting 2026-10-26, §§ 5–8; ADR 0047; `docs/plans/archive/HELP.md`). F1 shows the topic for where the person is, as Agenda's: its title, a blank line, its text, with links to other topics in bold (`Agendum.TUI.Help.Topics`). A place's topic is its F1 text (Views, Category Manager, View Manager, Note Editor …); a box's is its text and its settings' help ("Undiscard Box"); the menu's is the level shown ("Main Menu", "File Maintenance Menu"). Agenda's keys: ↑ ↓ ← → HOME END highlight a link (without links they scroll), a letter the next link it begins (none: nothing), ENTER reads the highlighted one, PGUP PGDN scroll, F1 How to Use Help, F3 the Help Index (the letters, each leading to its page of keywords), F5 Find (Agenda's Find Topic box, "Topic to find:", typed at once; ENTER opens its Select Help Screen box: the topics whose title has the word, then those whose text has it; ENTER reads one, ESC goes back; ALT-N / ALT-P then step through them), F6 Keys, F8 or BACKSPACE back through the topics read, F9 or ESC leave; other keys do nothing. The key bar is Agenda's: F1 On Help, F3 Index, F5 Find, F6 Keys, F8 Review, F9 Return. **Keys** is every key from the keymaps (R65's `a`), under two links: **Commands you can run here** (R65's `c`) and **Describe a key** (R65's `d`); ESC on those pages goes back to the topic. The Help Index is Agenda's kind (the owner's choice, 2026-10-26): F3's letters lead to keyword pages, each heading with its sub-entries ("Add ▸ Categories, Items"), from the topics' `INDEX` lines, a box also under Boxes and a menu under Menus. Written topics are text files (ADR 0047); the checks keep every box, place and menu with a topic and every link leading to one.
- **R66 ✅ Core commands** (not in Agenda; ADR 0036, `docs/plans/MULTIUSER.md` §7). Every change to the file is a named command the core runs (`Agendum.Core.run/3`): data such as `{:mark_done, [42, 43]}`, naming what it acts on by id, never by the highlighted row, so a web page, an agent or a command line can send it as well as the keyboard. The core checks the command and its arguments (an unknown command or the wrong number of arguments: `:unknown_command`, `:bad_arguments`; an id not of its kind in the file: `:no_such_item`, `:no_such_category`, `:no_such_view`, `:no_such_macro`, `:no_such_calendar`; blank text where text is needed: `:empty_text`; and the reasons the action itself gives, such as `:protected`), applies it, and returns the new file with what changed: the ids of items, categories, views, macros and calendars added, changed or removed, the file's settings changed, and the id of what it made (`new`), found by comparing the file before and after. A refused command changes nothing. `{:batch, commands}` runs several as one change, and makes none of them if one is refused. Each command has a name, a summary and the kinds of its arguments (`Agendum.Core.Command.describe/1`, `ids/0`). The front end turns the highlight and the marks into ids, words a refusal, and may preview a command (run it on a copy that is not kept) while the person chooses. A command is one step for undo (R30). The clock's own changes (alarms rung, old alarms forgotten, conditions rechecked on a new day) are commands too, and are not undo steps. Changes the commands brought: done on marked items gets the done time where a date category keeps one, as one item always did; ALT-F7 on text of only spaces in a note makes no item.
- **R32 ✅ Automatic completion** (User's Guide 2-19 to 2-21). While a category name is typed into a column cell, it is typed on the control panel's second line, as Agenda's (checked in Agenda 2.0, 2026-10-25; the owner's choice), with the first matching category's name after what is typed (the rest in grey); the cell keeps what it holds until ENTER. The first line says, in Agenda's words, "1 of 2 matching categories. Current choice: High;Hi" (the name, short name and Also match words), "No matching categories.", or before anything is typed "Enter category name:", and AUTOC shows at the right. The key bar is Agenda's: Help, Choices, NewCat, PrevSel, NextSel. Matching is on the start of names, ignoring case and accents ("éc" matches écrit and economy), among the column head's subcategories only, with an exact name first and then hierarchy order. ENTER accepts the shown match; F8 / ALT-N and F7 / ALT-P cycle through the matches (wrapping); typing more starts again at the first. INS, CTRL-N or F5 (NEWCAT) create exactly what was typed, even when it begins an existing name (Low when Lowest exists). With no match, ENTER creates the new category. F3 (CHOICES) opens the column's list of categories, as F3 on the entry does. The beeps are R76's. A date or a number is typed the same way, under "Date:" or "Number:" (both checked in Agenda 2.0, 2026-10-25), a Category note's line under "Line 2 of the category's note:", with EDIT; and a category's name, in the category manager (F2, INS and the ALT inserts: a new category a blank highlighted row in the list), a section head in a view (F2) and a box's head or new section, under "Category name:", the list, the head or the box keeping the name it has until ENTER. A box's field that holds a category (a column's or a section's head, a new section in View Properties) completes the same way, every category matching, as Agenda's (checked in Agenda 2.0, 2026-10-25; the owner's choice): typing shows AUTOC and the completion line, ENTER takes the match shown, F8 / F7 (ALT-N / ALT-P) go through the matches, F5 or INS take exactly what was typed (a name several categories have then asks for the picker), F3 drops the typing and opens the field's list; F2 there edits the name as it is, under "Category name:" with EDIT, without completion, as Agenda's EDIT. In the assignment profile F2 (EDIT) renames the highlighted category the same way, under "Category name:" (Entry, When and Done cannot be renamed), as Agenda's.
- **R76 ✅ Agenda's sounds** (User's Guide 2-19 to 2-21, 15-6; Setting Up Agenda 1-25; Working with Macros 1-5; ADR 0042). Agendum makes Agenda's own PC-speaker sounds, square waves with Agenda's frequencies and lengths (read from its program and checked against recordings of it in DOSBox; a timer tick is about 3.43 ms): typing a category name where automatic completion applies (R32: a column cell, the Item Properties box) gives a **high beep** (1200 Hz, 6 ticks) when the typing comes down to exactly one matching category and a **low beep** (140 Hz, 6 ticks) when no category matches, once on getting there and not again for each key while it stays so, as Agenda; F2 on a filled cell is not typing and does not beep. A key that shows an **error message** beeps (225 Hz, 30 ticks). Each key **recorded in Learn mode** clicks (75 Hz, 6 ticks; R50). An **alarm** plays Agenda's tune: three low notes (520 Hz) and three high ones (1040 Hz), each 50 ticks with a pause of 33 (R38). Two settings in Utilities ▸ Customize, kept in the preferences (R54): **Sound** (Yes, the default, or No: no sound at all; `sound = no`) and Agenda's **Beep on auto-completion** (Yes or No; `beep_on_completion = no`). The sounds play through the computer's own player (`afplay` on a Mac, `paplay` or `aplay` on Linux), in the background; with none, or over ssh, the terminal's bell rings instead, one sound for all. Ours: Agenda had a second, shorter error beep (12 ticks) for some refusals; Agendum uses the one error beep for every error message.
- **R33 ✅ Collapsing and expanding** (User's Guide 16-8 to 16-9, 5-5). Wherever the category hierarchy is shown (category manager, category box, assignment profile), ALT-− collapses the family the highlight is in (its own children if it has any, otherwise its parent's) and pressed twice collapses every family; ALT-= expands the highlighted family and pressed twice expands everything. A collapsed parent shows "...". The assignment profile still shows categories the item is assigned to. Our choices: collapsed families are a display setting kept for the session (shared by all those screens, not saved in the file and not undone), and moving a category into a collapsed family expands it so it stays in sight. In a view, the same keys collapse and expand the current section (twice: all sections), shown with "§".
- **R34 ✅ Item Properties box** (User's Guide 4-13 to 4-15). F6 on an item (or Item ▸ Properties) shows its text (F2 edits), note (SPACE or F2 opens it), statistics (number of categories, entry date) and every assignment in hierarchy order: dates in parentheses, conditional assignments marked "(c)". DEL breaks an assignment (the Entry date cannot be removed); F4 changes a date or number; ENTER closes the box (§5); typing assigns a category, with automatic completion over all categories (R32), asking for the date when a date category is chosen; INS creates exactly the typed name under MAIN; F3 opens the assignment profile. Not done: note files.
- **R35 ✅ Marked items** (User's Guide 13-1 to 13-4, 4-5, 4-17). F7 marks an item (♦, CP437 0x04, as Agenda's screen draws it; R59 has its place in the row); while any item is marked, ♦ also stands in column 78 of the control panel's second line, after # and ♪, as Agenda's (checked in Agenda 2.0, 2026-10-25); on a section head it marks every item in the section, or unmarks them when all are marked. ALT-F7 unmarks everything; ALT-J jumps to the next marked item in the view. With items marked, these commands first ask "Marked items (N) / Current item": F4 done (marked items are all set done), ALT-F4 discard (then Y/N), DEL remove from the current section, ALT-F2 When date, ALT-F10 move (the items keep their order), ALT-M MakeAssign (category box; also for a single item), and F3, which shows a group assignment profile: a number beside each category says how many marked items are in it, and SPACE assigns or unassigns them all. Our deviation: marks belong to the item, not to one section, so a marked item shows marked everywhere; a moved item leaves the first section of the current view that holds it. ALT-F9 copies the marked items, or the current one, to another section (R42).

## 5a. Data interchange

- **R44 ✅ JSON export and import** (not in Agenda; ADR 0010). File ▸ Transfer ▸ Export writes the whole file as readable JSON (the name offered is the file's, with `.json`); File ▸ Transfer ▸ Import reads one and opens it as a new, untitled file, to be saved under a name (the open file is replaced, as with Retrieve; nothing is merged). Like Retrieve and New, and as Quit already did, it first asks "Save changes first? (Y/N, ESC to cancel)" when the open file has unsaved changes: Y saves (asking for a name if it has none) and goes on, N goes on, ESC cancels. Everything in the file survives a round trip: categories and their properties, items with their assignments, dates, numbers, dependencies and suggestions, views, and the file's settings; the person's own settings (theme, languages, input format) are not in it. Import checks types and references and says what is wrong and where; a file that fails opens nothing. The schema is `docs/JSON_FORMAT.md`. Agenda's own transfer format (STF) and its `.AG` files are optional roadmap items (Data interchange).
- **R72 ✅ Importing a Lotus Agenda file** (ours, as old Agenda users need it; expert reviews 2026-10-16, meeting 2026-10-16-2; decisions 2026-10-16). File ▸ Transfer ▸ Import takes a Lotus Agenda 2.0 data file (`.AG`) as well as JSON, told apart by their contents ("JSON or Agenda (.AG) file to import"), and `agendum OLD.AG` imports one from the command line. The file opens as a new file of the same name with Agendum's extension beside it (`OLD.agendum`), not saved yet; at the first save, a file already there is asked about (R71). A file with a password asks for it ("Password of OLD.AG:", the text shown as stars and kept out of the debug log); as in Agenda, case does not matter, and a wrong one says "The password you typed is incorrect. Retype the password of OLD.AG:" (checked in Agenda 2.0). What comes over: the category tree with names, short names, Also match, exclusive children, notes, conditions, actions (assign as a category link, R8; remove), the Done and Discard special actions, text matching settings of their own and the date categories' rules; items with text, note, Entry, When (its time, and a recurring rule as Agendum's, R14a) and Done dates, the dates of the user's date categories, numbers, and alarms on When; views with sections, columns (width, number format), sorting, filters (relative dates become phrases Agendum reads, "yesterday", "end of this week"; others stay as dates), the hide options and section order; datebook views from their period and hours, starting from today. Items in Agenda's trash go to ours, text and note, counted from the day of the import, and File Properties ▸ Empty trash comes over (R24a). Assignments made by hand in Agenda are kept; the others (text matching, conditions, actions) Agendum works out again by its own rules (as Utilities Execute, R15e). An unindexed category stays unindexed, each item's value its text (R29b). Afterwards the **Imported from Agenda** box reports the counts, what was left out or simplified (macros, note files, other alarms, datebook start dates) and the items Agendum files differently from Agenda (+ a category added, − one not kept); ↑ ↓ PGUP PGDN scroll it, CTRL-P writes it to `OLD-import.txt` beside the Agenda file, ENTER or ESC closes it. The reading follows `docs/AGENDA_FILE_FORMAT.md` (`Agendum.Core.AgFile`, pure, through `Core.import_ag/2`). Not yet: macros, note files, the global date format, Agenda's own print settings.
- **R45 ✅ Calendar subscriptions** (not in Agenda). File ▸ Transfer ▸ Calendars lists the file's subscriptions to calendars on the web (iCalendar `.ics`, `https://` or `webcal://`). INS asks for the address and a name; the name is the category the events go in, its own (without name matching, never a category of the person's with that name), in the family the other calendars share, else in **Calendars** under MAIN, made when first needed (R75a; the owner, 2026-10-26), and the calendar is read at once. ENTER reads it now; F sets how often it is read while Agenda runs (every hour, the default; every 6 hours; every day; only on request), A how far ahead it imports (30, 90 by default, 180 or 365 days); DEL unsubscribes, Y also discarding its items, N keeping them. Each calendar shows when it was last read, or why that failed. A read mirrors the calendar: an event from today up to the window ahead becomes an item in the category, its title the item text (read like typed text, so text matching files it too), its description the note, and its start the When date and time, set as by hand; its end (DTEND, or DURATION) goes in the date category Ends, made under MAIN the first time an event has one (a category of that name that is not a date category is left alone): a timed event's end date and time, an all-day event's last day when it lasts more than one, a repeating event's end keeping its length on the next date; a repeating event becomes one item on its next date, with Agenda's recurrence (R14a) when it repeats the same way (daily, weekly on one day, monthly on one day, yearly, every n of them), else only that next date; a series that has ended is not imported. A later read changes only what the calendar changed (the person's edits to text and note, their categories and done marks stay), and an event gone from the calendar or cancelled removes its item; an item the person discarded is not brought back, and past events keep their items. A read is one undo step; a scheduled read is quiet unless something changed. Reading happens in the background (the screen does not wait), with the system's certificates checked. Our choices: there is no time-zone database; a time in a named zone is converted by the calendar's own definition of that zone (VTIMEZONE: its offsets and yearly daylight-saving rules, as calendars from Google, Apple and Microsoft include them) to UTC, and UTC times to local time by the system's rules; a zone the calendar does not define is taken as local time. A repeating event keeps the local time of its first occurrence, so where the calendar's zone and yours change to summer time on different days, a few weeks of a year may be an hour off; alarms, attendees and exceptions to repeating events are not read. Subscriptions are saved in the file and in its JSON.

## 5b. Calendar, datebooks and schedules

- **R46 ✅ Pop-up calendar** (User's Guide 6-14 to 6-17; Help "Use the Pop-Up Calendar"). F3 (CHOICES) on a column entry in a date column opens a month calendar on the entry's date, or on today when it has none; ALT-C opens it anywhere in a view, on today, for reference. ← → move a day, ↑ ↓ a week, HOME / END to the first / last day of the month, PGUP / PGDN the same day a month back / ahead, CTRL-← / CTRL-→ a year (Mac: `<` / `>`); a month or year move keeps the day where the month has it. Typing a date ("next friday", "2027-03-15") jumps there (Agenda shows what is typed at the top: here the control panel's prompt); F6 (SETTIME) asks for a time to go with the date (empty: none). ENTER sets the date, and the time, in the entry as if typed there (so When is set by hand, R14, date rules and conditions follow, one undo step); for reference it closes. ESC changes nothing. Dates run from 1 AD to 5000, as in Agenda. Our choices: the week starts on the file's Beginning of week (R14e; Agenda's screen started on Sunday), the calendar keeps the entry's time unless F6 changes it, and Agenda's Set Time box (SPACE between hours and minutes, GREY + / −) is a typed time.
- **R47 ✅ Datebook views** (User's Guide chapter 10, 10-1 to 10-14; Help "View Add box", "Browse Through Dates"). A datebook view is like a page of an appointment book: its sections are time slots, all headed by one category. Settings: Date category (When by default) places items by their date; End category (optional, a date category) shows an item in every slot up to its end ("Status meeting" 14:00 to 17:00 shows at 14, 15 and 16); Section, the head of every section (the date category by default; Meetings shows only meetings); Period, Day, Week (default), Month or Quarter; Interval, what a slot covers: 15 min, 30 min or Hourly (default) for a day, Daily or Weekly (default) for a month, Daily, Weekly (default) or Monthly for a quarter, a week having a slot per day; Start at / End at, the hours of a day (default the file's Morning and Evening, 8:00 and 17:00) or the days of a week (default the file's beginning and end of week, Mon and Fri); Base date on, a relative or absolute date ("today", "tomorrow", "next week", "2026-11-05") read each time the view is shown, the period being the one it falls in (a month's and quarter's weeks run from the file's beginning to end of week and may reach into the next month; quarters start in the file's first quarter month). An item shows in a slot when its date (and time) in the date category falls in it; an item typed into a slot is filed under the Section category and dated at the slot's start, with its time in a day view, as if typed in the date column (so "Status meeting" typed under 16:00 today is When today 16:00). Restrictions as in Agenda: a datebook view cannot become a standard view, its sections cannot be added, removed or filtered one by one (view filters apply to all). Deleting a category it uses falls back to When. Our choice: in a day view, items with that date but no time are in a first slot named after the day, above the hours; items timed outside Start at to End at are not shown. In the TUI: View ▸ Add (or INS in the view manager) asks for the name, then the Type, Standard or Datebook; a datebook view starts with Agenda's defaults and opens its View Properties, which holds the datebook's settings in its right column instead of Sections, as Agenda's (checked in Agenda 2.0, 2026-10-25): Date category, End category, Section, Period, then Interval, Start at and End at as the period has them (a day all three, a week Start at and End at, a month or quarter Interval), Base date on; it has no Section sorting (SPACE picks a category or types a time or base date, SPACE/→ ← cycle Period, Interval and a week's days, DEL clears the End category; a time without am/pm is read as everywhere, R14b). Each slot's head is a line across with its name, in the file's date format ("── Mon 2026-10-12 ──", "10:00", "Mon 2026-09-28 → Fri 2026-10-02", "October 2026"), without a blank line above; the control panel says "Datebook For: When" (the Section) from column 40 of its second line, as Agenda's, and the view manager marks datebook views with *. Typing into a slot dates the item; ALT-D/U, DEL or F3 on a slot, collapsing, section filter and sort, and ALT-F10 say why not. Browsing (View ▸ Browse or ALT-B, BROWSE at the top right): ← → (or < >) show the previous / next period, ALT-F5 asks for a date and shows its period, ENTER keeps the period shown (the base date becomes its date, one undo step; a view based on "today" then stays there until Base date on is set again, as in Agenda) and ESC goes back; while browsing nothing else can be done. Standard views with date filters are browsed too (R48), and Show Schedule shows one date (R49).
- **R48 ✅ Browsing date filters** (Help "Browse Through Dates"). In a standard view, View ▸ Browse or ALT-B moves the date filter of the highlighted section, when it has one, else the view's: ← / → a day, CTRL-← / CTRL-→ (or ↑ / ↓) a week, PGUP / PGDN a month, CTRL-PGUP / CTRL-PGDN (⌥↑ / ⌥↓ on a Mac) a year; ALT-F5 moves the range to start on a typed date. Each end of a date range is read against today, moved, and shown as a fixed date (the view's line shows them; open ends stay open; numeric ranges and category criteria do not move); items come and go as the dates move. ENTER keeps the moved dates in the filter, one undo step ("today".."end of this week" becomes, a week on, "2026-10-19".."2026-10-23": fixed, no longer following today, as in Agenda); ESC puts the filter back. F8 (DEFAULT) goes back to the dates browsing started from, and F10 (MENU) leaves browsing, its dates given up, for the menu (checked in Agenda 2.0, 2026-10-26). Without a date filter, ALT-B says so. The control panel says Agenda's words, "Use the cursor keys to display schedules for other dates." with BROWSE alone at the right, and "Current filter:" with the browsed dates under it (a datebook: "…other periods." and "Right arrow moves forward, left arrow moves back one period."); nothing else can be done meanwhile.
- **R49 ✅ Show Schedule** (User's Guide 10-14 to 10-16; Help "Show Schedule Box"; Agenda's Utilities Show Sched). Utilities ▸ Show ▸ Sched opens the Show Schedule box: Date category (When by default; must be a date category), Section head (the date category by default), Date (today; typed, or F3 for the pop-up calendar, R46) and Filter (categories whose items to show, + assigned or − not assigned, as in a view filter). SPACE changes the highlighted setting, ENTER shows the items of that date in the Show View under the section head, ESC cancels. The date is a date filter on the Show View ("[When 2026-12-14..2026-12-14]"), so ALT-B browses it to other days (R48). The Show View starts afresh each time it is used, by a schedule, a search (R37) or a dependency list (R43): its section and filter are those of the last use.

- **R75 ✅ Feeds: a plain RSS reader** (ours; meeting 2026-10-16-2, § 7; the owner's decisions, 2026-10-17, `plans/RSS_READER.md`). File ▸ Transfer ▸ Feeds lists the file's feed subscriptions, as the Calendars box does calendars (R45): INS subscribes (the feed's address, `https://` or `feed://`, then its name), ENTER or R reads the highlighted one now, F changes how often it is read (every hour by default, 6 hours, a day, or only on request; also when Agendum starts), K how long its entries stay (30 days by default, 7, 90, 365, or for ever), DEL unsubscribes, asking whether to discard its items too, I imports an OPML feed list (the feeds the file does not have yet; folders read through) and E exports one (`feeds.opml`). RSS 2.0, RSS 1.0 and Atom are read; a feed that is broken is read as far as it goes. Each entry becomes an item in **Feeds ▸ the feed's name** (both made when first needed, without name matching): its title the item text, its summary as plain text (HTML read as text, at most about 2,000 characters) and its link the note, its publish date the **Entry** date. Text matching, conditions and actions file it as a typed item, but dates in a title are not read: When stays empty, so feeds stay out of date views and the calendar. The first feed makes the **News** view: a section per feed, newest first by Entry date (a column shows it), done items hidden. A later read adds new entries and changes an entry's item where the feed changed it and the person did not; the message line says "Owl's Gazette: 3 new, 1 changed, 2 faded" (from the box, also "nothing new" or why the read failed). Nothing asks to be read: there are no unread counts, and F4 Done dismisses an entry. An entry older than the feed's days **fades** (its item is discarded) unless it was **kept**: given a Zettel id (R73), its text or note changed by the person, or a category given by hand (not by text matching or a condition); Done does not keep it. An entry that faded or that the person discarded is never brought back: the file remembers only its id and publish date, not its text (format 45; meeting 2026-10-26-4, § 5). **CTRL-V** (or Item ▸ Open link) opens the first web address in the highlighted item's note, else its text, in the browser (`open` on a Mac, `xdg-open` elsewhere); only `http(s)` addresses. Feed text is data, never instructions: it is stored as text, never shown as markup, and nothing in it runs.
- **R75a ✅ Ingested categories** (ours, an extra; meeting 2026-10-26-5, § 6; ADR 0048). The categories a feed or a calendar files into, each feed's category under Feeds and each calendar's under Calendars, and the extras' families themselves, **Feeds** and **Calendars** under MAIN while each holds at least one subscription, are **ingested**: the extra names and fills them; the person reads them but does not change or fill them. They head sections, filter views and are read by conditions (a condition on the person's own category may test one). Refused, with "Heffalump News is filled by a feed: rename or remove it in File ▸ Transfer ▸ Feeds" (or "… by its calendar … Calendars", "Feeds holds your feeds …"): renaming, a note, Also match, conditions and actions, exclusive children, moving, sorting, discarding, a new child, and, for a feed's or a calendar's own category, filing an item into it by hand, from a column, by typing in its section, or by another category's action. A family locks only its structure: a category the person kept when unsubscribing stays theirs inside it, and the family stays the extra's (with its other subscriptions) while it holds one. A name is one subscription's: a second feed or calendar of the same name is refused ("… is taken"). In the category manager the message comes at once, before anything is typed; elsewhere the key stops with it. The **Feeds and Calendars families start folded** in the category manager, one line each, and ALT-= opens one (ALT-− folds it again). A family of the person's under MAIN that holds only calendars' categories is named **Calendars** as a file is opened, unless one is already there (the owner's "Kalender" became Calendars); nothing moves as a file opens, but calendars that versions before 0.68.0 made straight under MAIN join Calendars when the next calendar is subscribed. A calendar in a family of the person's among their own categories stays where they put it, and new ones go to Calendars. Both boxes scroll by whole feeds or calendars when there are more than fit, the highlighted one always shown, with "▲ 3 more above" and "▼ 230 more below". **F2 in the Feeds and Calendars boxes** renames a feed or a calendar, and its category with it ("New name of the feed:"); two feeds, or two calendars, cannot share a name. Which categories are ingested is worked out from the subscriptions, never stored: unsubscribing hands the category back, an ordinary category of the person's again, and so does the Feeds parent once no feed is left. 

## 5c. Macros

- **R50 ✅ Learn-mode macros** (Working with Macros, chapter 1). A file keeps macros (Agenda allowed 100): each has a name of up to 35 characters, unique case aside, its keystrokes, the key it is attached to (a key belongs to one macro at a time) and where it can be run from: views, notes and the category manager (Yes by default) and, for an attached key, everywhere else (No). They are listed in the macro manager's order, which can be changed or sorted by name. Keystrokes are kept as text in Agenda's notation (1-12 to 1-14): text as typed, other keys as names in braces, read in any case: `{ENTER}`, `{TAB}`, `{ShfTAB}`, `{BS}`, `{DEL}`, `{INS}`, `{ESC}`, `{UP}` `{DOWN}` `{LEFT}` `{RIGHT}`, `{HOME}` `{END}`, `{PGUP}` `{PGDN}`, `{CtlLeft}` and the other CTRL arrows, `{F1}`..`{F12}`, `{AltF1}`.., `{CtlF1}`.., `{ShfF1}`.., `{AltD}` (ALT and a letter), `{CtlN}` (CTRL and a letter). As in Agenda, a misspelt name is typed as written, line breaks are not keys and the spaces that start a continuation line are left out (a line's end keeps them). Ours: `{LBRACE}` and `{RBRACE}` type braces; keys Agenda had no name for get one in its style (`{AltBS}`, `{AltShfD}`). Saved in the file (format 24) and its JSON. ALT-F3 (MACRO) opens the macro manager: INS (or CTRL-N, or typing) names a new macro; F7 (LEARN) closes the manager and records: LEARN shows at the top right, every key does its usual work and is recorded, in views, notes, the category manager and boxes alike (keys, not their meanings: F7 recorded in the category manager marks when played in a view); ALT-F3 (or ALT-Z) stops ("Learn mode is off: Weed has 19 new keys"). F7 on a macro with keystrokes asks whether to replace or append them. ENTER on a macro runs it where you were; ALT-Z runs the macro run last again. A run plays the keys one by one as if typed, saving, opening files or asking questions on the way (the shell runs each key's effects before the next), and is one undo step; a run that changed nothing is none. Our choices: ALT-F3 and ALT-Z do nothing over a line being typed, a prompt, a question or the menu (in Learn mode they still stop); within a run ALT-Z does nothing (Agenda could not record it); runs started from runs stop 8 deep ("Macros started 8 deep; stopped"); each recorded key clicks, as in Agenda (R76). In the manager F2 opens the macro edit screen, the note editor with the keystrokes as text (a line after each {ENTER}; saved on leaving), F6 the Macro Properties box, laid out as Agenda's (checked in Agenda 2.0, 2026-10-25; its Macro file and protection left out): Name (F2 or SPACE renames), Contents ("...": SPACE or F2 edits the keystrokes), Attach to key (SPACE asks for one key in the notation, `{F4}`, `{ShfF4}`, `{CtlE}`; DEL detaches; ALT-F1, ALT-F3 and ALT-Z cannot be attached) and, under "Macro can be run from:", View, Note, Category manager and, ours, for an attached key only, Everywhere else (SPACE switches Yes / No). An attached key runs its macro where the macro may run, instead of its own command; a function key attached to a macro shows the macro's name in the key bar. Within a run an attached key does its own work, as in Agenda; `{CALL Name}` runs another macro (Agenda's {CALL}), and Learn mode records a key attached to a macro as such a call, not the keys that macro plays. DEL deletes a macro after asking, ALT-F5 sorts the list by name. Ours: ALT-↑ / ALT-↓ move a macro in the list, as in the view manager (Agenda: ALT-F10 then ENTER). Not done: the macro command language (Working with Macros, chapters 2–3), external macro files, protection and hidden macros. The macro manager is drawn as Agenda's (checked in Agenda 2.0, 2026-10-25): titled Macro Manager, Agenda's help on the control panel ("Highlight the macro you want to run or change. Press ENTER to run the macro, INS to create one, F2 to edit an existing one."), and its key bar, F2 EditMac, F4 Delete (as DEL), F6 Props, F7 Learn; like Agenda's view manager, it has no F10 menu.

- **R54 ✅ More preferences** (Setting Up Agenda 1-25 to 1-28; User's Guide 2-22 to 2-23). More of Agenda's Utilities Customize settings, in Utilities ▸ Customize, kept in the person's preferences file like the rest (ADR 0008):

  - ✅ **Confirm mode** (Yes, the default, or No): with No, Agendum does what was asked without "are you sure?" questions: discarding items, categories and views, deleting macros, clearing dependencies, sorting a family, changing a category's type, making an item depend on others. Questions whose Y and N do different things are still asked: "Save changes first?" and, when unsubscribing, whether to discard the calendar's items too. Undo (R30) still reverses what was done.
  - ✅ **Auto-save interval** (User's Guide 22-8): a file with a name and unsaved changes is saved once no key has been pressed for that many minutes (not while a settings box is open: its changes reach the file on ENTER), with the usual "Saved" message. Off (the default) or 1 to 60 minutes; Utilities ▸ Customize steps through 1, 2, 5, 10, 15, 20, 30, 45 and 60, and `auto_save = N` in the file takes any of them. An untitled file is never saved by itself. A save that fails is tried again an interval later.
  - ✅ **Decimal separator** ("." the default, or ",") and **Thousands separator** ("," the default, ".", or a space; Setting Up Agenda 1-25, 1-28): how numbers are shown and read everywhere: column entries and calculations, typed numbers, range filters and conditions, actions, Item Properties, and category names read as numbers. The two are never the same: with a decimal comma the thousands separator is a dot unless a space is chosen. They belong to the person's input format, so they reach the core with the clock (`Agendum.Core.Context`), as dates do (`decimal_separator` and `thousands_separator = space` in the file).
- **R68 ✅ The current view and recently used views in the view manager** (ours; meeting 2026-10-16, § 7 and § 8). The view manager shows ► before the name of the view shown, in a column of its own beside the datebook `*`, wherever the highlight goes, so "where am I?" is answered at a glance. Agenda's view manager marked nothing once the highlight moved. F5 lists the views by when they were last shown, the view shown first, then those never shown in the file's order, with "View Manager: recently used" as the title; F5 again goes back to the person's order, the highlight staying on its view each time. Only the list changes: the file's order, which ALT-N, ALT-P and hop follow (R42), stays, and ALT-↑, ALT-↓ and ALT-F5 (which change it) say "Listed by recently used: F5 shows your order" instead. The setting starts off and stays as set; it and the views used (the last 50) are the person's, kept with where they left the file (R69, `recent:… order:recent`) and saved as F5 is pressed. Agenda had only the one-off sort by name (ALT-F5, User's Guide 9-16).
- **R69 ✅ Where you left a file** (meeting 2026-10-16, § 5). A file opens on the view and the item that were highlighted when it was last left (by Quit, or by Retrieve, New or Import opening another file); an item no longer there leaves the highlight on its section's head, a section no longer there on the top of the view, and a view no longer there opens the file on its first view, as before. The views used lately and how the view manager lists them go with the place (R68). Agenda stored the current view and item in the file (`AGENDA_FILE_FORMAT.md`, header `0x044` and `0x1E8`). Ours: the place is kept in the person's preferences, by the file's path (`place = view:3 section:2 item:17 file:/path`, the 50 files left last), never in the file, so moving around never makes the file changed or causes a "Save changes?" question, and each person has their own place in a shared file. A copied or renamed file opens at the top.
- **R71 ✅ A file changed on disk** (ours; meeting 2026-10-16-2, § 8). Agendum does not save over a file that another writer (another Agendum, a sync tool, an agent, later capture from outside) changed since Agendum read it or last saved it, without asking. It keeps a stamp of the file's bytes (an MD5 sum) from when it read or wrote them; a save that finds other bytes there asks "garden.agendum has changed on disk since Agendum read it. Save over it?" (Yes, as the other questions, R54). Yes saves over it; No saves nothing and says that File ▸ Maintenance ▸ MakeCopy writes the changes to another file, keeping both (R82). A file not on disk when it was opened or made with New, that is there at its first save, asks the same with "already exists"; a file removed since is written again without asking. Auto-save (R54) never asks while the person may be away: it says "Not auto-saved: … changed on disk" and stops auto-saving until a save the person makes settles it. What follows a save waits for it to succeed: Quit after Yes to "Save changes before quitting?" quits only once the file is saved, and a save that fails or is refused leaves Agendum open with the changes ("Could not save: … (not quitting)"); after Yes to "Save changes first?" the Retrieve, New or Import prompt comes only then; Save As takes the new name only once saved there. The check is in the shell (`Agendum.Store.save/3`), so the core stays pure; another writer changing the file in the instant between the look and the write is not caught. Save As over another existing file still writes without asking, as before.
- **R77 ✅ The Extras preference** (ours; ADR 0043; meeting 2026-10-21, § 7; settled with the owner 2026-10-23). Agendum's extras, the features Agenda did not have that fail ADR 0043's test of a truthful clone (`plans/AGENDA_PARITY.md`, tag *extra*), are hidden behind one preference, **Extras** in Utilities ▸ Customize (No, the default, or Yes; `extras = yes` in the preferences file, R54). With it off: the extras' commands are tagged in `Agendum.TUI.Commands` and left out of F1's command list, CTRL-X and describe key, and their keys do nothing, as unbound keys (CTRL-T, CTRL-G, CTRL-R and CTRL-V in a view, CTRL-L in a note, F5 in the view manager); the menu leaves out File ▸ Transfer ▸ Calendars, Publish and Feeds, Item ▸ Open link and Item ▸ Zettel; the view manager shows no ► (R68) and lists the views in the file's order; the key bar keeps Agenda's short labels on a wide screen; feeds and calendars are not read on schedule (R45, R75), so nothing goes to the network unasked; and alarms that came due while the file was closed ring as Agenda's do, a message and the alarm's sound, the items showing `@`, with no "While you were away" box (R70). The file's data stay and show as they are: Zettel ids, a Zettel id column, feed entries, the News view, the blog's settings; a file saved with Extras off keeps the extras' fields unchanged. Switched on, everything comes back at once. Faithful code reaches the extras' boxes only through doors listed, with their reasons, in the architecture test (ADR 0044).

## 5e. Zettels

- **R73 ✅ Zettel ids** (ours; meeting 2026-10-16-3, § 5 and § 6; ADR 0039). An item can have a Zettel id: eight pronounceable letters in four syllables, such as `bonalaku`, the Quadsyl-24 spelling of a number (`docs/QUADSYL.md`, `Agendum.Core.Extras.ZettelId`). An item with an id is a zettel. Item ▸ Zettel ▸ Attach gives the highlighted item the next id; with items marked it asks, as other commands do, "Give a Zettel id to:" the marked items or the current one. The message line says which id was given ("bonalaku given"; "2 Zettel ids given: bonalaku, pigavono"); an item that has one keeps it ("The item already has its Zettel id, bonalaku"). Ids are given in order from the file's own counter, from 1, skipping the 267 real words, which are reserved for special notes (not given out yet); an id is never given twice, not even after its item is discarded, and never changes. One undo takes the ids back. CTRL-T (the owner's choice, 2026-10-17), the menu, or the command list.
- **R73a ✅ A Zettel id column.** A standard column's Format (Column Add and Column Properties, R56) can be **Zettel id**: the column shows each item's id, whatever the column's head, under the head "Zettel id"; nine wide by default. Typing in it, or DEL, changes nothing and says "A Zettel id is given by Item ▸ Zettel ▸ Attach; it cannot be typed".
- **R73b ✅ Links between zettels** (ours; ROADMAP, meeting 2026-10-16-3; the owner, 2026-10-16). In an item's text or note, `[[bonalaku]]` is a link to the item with that Zettel id, and so is the id written on its own (`bonalaku`) when an item has it; case does not matter, and an eight-letter word no item has stays plain text. Links show in the link colour of the theme, in the view and in the note editor; a bracketed link no item has is *broken* and shows in a colour of its own. With the cursor on a link, in a note or an item being edited, the control panel shows what it points at ("→ bonalaku: Owl's birthday", or "[[kitolido]]: no item has this Zettel id"). Item ▸ Zettel ▸ Follow shows the items the highlighted item links to (its text first, then its note, each once) in the Show View, and Item ▸ Zettel ▸ Linked shows the items that link to it, the way ALT-O lists dependencies; ALT-F8 goes back. Item Properties shows the item's id before its statistics and lists the items linking to it under **Linked from** (SPACE shows one). In a note, **Insert link** types `[[…]]` for each marked item at the cursor (they need ids). Text matching ignores bracketed links, so `[[bonalaku]]` never files an item under a category of that name. Keys (the owner's choice, 2026-10-17): CTRL-G follows, CTRL-R shows Linked from, CTRL-L inserts a link in a note.
- **R74 ✅ The micro-blog** (ours; the owner's own use, VISION group 1; meeting 2026-10-16-2, § 8; the owner's answers 2026-10-16; ADR 0041). File ▸ Transfer ▸ Publish writes a blog from the file as a static website. The **Publish the blog** box holds its settings, kept in the file: the **Posts category** (Posts by default) whose items are the posts, the **Drafts** category whose posts are left out until ready (none by default), a typed name no category has being made under MAIN; the site's title, description, author, language, **base address** (for the feeds' whole links), `rel="me"` links to the person's other profiles, the **folder** it is written to (`site` beside the file by default; any path, a mounted one too), and **Upload**: None, rsync over ssh (to a target such as `me@host:www/blog`) or SFTP (to a host, `host:port`, as a user, into a folder there). A letter on a text field types it, SPACE or F2 edits it; ESC closes the box and changes nothing. A post is the item's text as its title and its note, in Agendum's **Markdown** (paragraphs, `#` headings, `**strong**`, `*emphasis*`, `` `code` ``, code blocks, quotes, lists, `[links](https://…)`, `![images](https://…)`, bare addresses, a rule `---`, and the task boxes `- [ ]` to do, `- [x]` done and `- [-]` cancelled, struck through), its date the When date, else the Entry date; posts come newest first. Anything else is text: HTML in a note is escaped, never markup. A link's text, a code span or an emphasis is at most 500 characters long; a longer one is text (our choice: so that a post of any size becomes HTML in time proportional to its length). **ENTER** keeps the settings and gives each post without a Zettel id one (R73), in one change (one undo step), and makes the site: `index.html` with every post in full, a page per post at `posts/<zettel id>.html` (an address that never changes), `rss.xml` (RSS 2.0) and `feed.json` (JSON Feed 1.1), and `style.css` with its fonts in `fonts/`. The design is [The Proportional Web](https://owickstrom.github.io/the-proportional-web/) by Oskar Wickström (MIT, credited in the stylesheet): Alegreya for text, Alegreya SC for headings, Courier Prime for code, all written into the site with their licence (`fonts/OFL.txt`), so no reader's browser asks Google or anyone else for them; dark when the reader's system is (`prefers-color-scheme`). `style.css` is written when the folder has none, or when it is still word for word the monospace stylesheet Agendum wrote before 0.69; one the person changed stays (owner's answers 2026-10-26). The pages are plain HTML without JavaScript, readable without the stylesheet, with microformats (`h-feed`, `h-entry`, `h-card`) and `rel="me"` links, so micro.blog or a bridge such as Bridgy Fed can follow the blog from the fediverse. A Zettel link in a post (R73b) is a link to the target's page when it is a post, else the target's text; a broken one stays as written. Agendum then reads the folder and the **Publish: what will change** box lists the files it would add (+), change (~) and remove (−, a post that is no longer one), and where they then go; ENTER writes them and uploads, ESC writes nothing ("Nothing was published"). Only Agendum's own files are written, removed or uploaded (it keeps their list in `.agendum-site` in the folder); nothing else in the folder or on the server is touched. rsync sends only those paths (`--delete` limited to them by filters, `-c` comparing contents). SFTP uses the person's ssh keys and `~/.ssh/known_hosts`; a server that refuses them makes Agendum ask "Password of user@host (not kept):", the typing shown as stars, kept out of the debug log, never stored; a `~/.netrc` password is used too. Afterwards the message line says "Published and uploaded: 2 added, 1 changed, 0 removed", or why not ("Not published: …"). Not yet: comments, tag pages, images uploaded from the file, publishing on a schedule. Publishing runs in the background: Agendum goes on while the site is written and uploaded ("Publishing …"), one at a time; an upload never waits for ever (SFTP calls time out, rsync's ssh never asks for a password or a host key). An SFTP upload sends the whole site each time, and removals a failed upload did not make wait in the folder (`.agendum-unsent`) for the next one. The posts and drafts categories stay the ones they are unless another name is typed, and a name two categories have is refused (code review 2026-10-26).
